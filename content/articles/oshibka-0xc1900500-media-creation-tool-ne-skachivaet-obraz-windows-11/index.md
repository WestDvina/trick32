Код `0xC1900500` — региональный отказ загрузки образа Windows 11 из России и Беларуси, и обойти его можно, временно сменив `CountryCode` в ветке CBS через ExecTI, скачав образ и вернув прежнее значение.

Страница загрузки вместо ссылки на ISO отдаёт «При обработке вашего запроса возникла проблема. Попробуйте позже», а Media Creation Tool закрывается с этим кодом. На момент публикации Microsoft проблему официально не подтвердила: отдельного документа про `0xC1900500` нет. Кода нет в справочнике mosetup, таблица современных ошибок установки заканчивается на `0xC1900405`, поэтому расшифровки кода в документации нет, но это не значит, что причина неизвестна: симптом повторяется у пользователей из России и Беларуси и совпадает с отказом самой страницы загрузки. Дальше это наблюдение, а не цитата из документации.

## Проверка локальных причин

Место на диске — не меньше 20 ГБ для 64-битной системы и 16 ГБ для 32-битной:

```powershell
Get-PSDrive C
```

Компоненты — из командной строки от администратора:

```cmd
DISM.exe /Online /Cleanup-image /Restorehealth
sfc /scannow
```

Если места хватает, обе команды отработали без ошибок, а страница загрузки и Media Creation Tool отказывают одинаково, искать локальную поломку на этой машине дальше бессмысленно: остаётся региональный сценарий, и дальше речь только о нём.

## Основной путь: ExecTI и CountryCode

Ветка `Component Based Servicing` принадлежит службе `TrustedInstaller`, поэтому `reg add` от обычного администратора возвращает ошибку «Отказано в доступе», а смена владельца ключа через regedit не помогает: запись параметра выполняет процесс с токеном службы, для чего и берут такую утилиту, как ExecTI.

1. Скачайте ExecTI с сайта автора, распакуйте и запустите `ExecTI.exe` от имени администратора.
2. Укажите программу `cmd.exe -m`, выберите режим **TrustedInstaller** и нажмите **Run**.
3. В открывшемся окне посмотрите текущее значение:

```cmd
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing" /v CountryCode
```

4. Поставьте `US`:

```cmd
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing" /v CountryCode /t REG_SZ /d US /f
```

5. Запустите `MediaCreationTool.exe` от администратора и дождитесь конца загрузки.
6. Верните значение из шага 3. Для `RU`:

```cmd
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing" /v CountryCode /t REG_SZ /d RU /f
```

Если параметра раньше не было, удалите его:

```cmd
reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing" /v CountryCode /f
```

ExecTI — сторонняя утилита, не компонент Microsoft: берите её с сайта автора, сверяйте хеш и помните, что способ не гарантирован, а значение `CountryCode` после загрузки нужно вернуть.

## Проверка файла

Microsoft публикует SHA-256 по языкам. Для русского 64-bit текущего выпуска:

```text
3DD71E8F84BFDC0054E1C4383DB2EAC921D21952AC03B2231CB6E9610A2F7423
```

```powershell
Get-FileHash .\Win11.iso -Algorithm SHA256
```

Совпал — файл целый. Не совпал — скачайте заново. Ссылка на ISO живёт 24 часа, а страница загрузки работает по тем же правилам, что и [официальная загрузка образа Microsoft](/articles/skachat-windows-original-iso-microsoft/).

## Что подтверждено, а что нет

Подтверждено Microsoft: кода `0xC1900500` нет в справочнике mosetup; страница загрузки отдаёт ошибку вместо ссылки; требования к свободному месту; команды `DISM` и `sfc`; таблица SHA-256 и срок жизни ссылки 24 часа; продажи в России приостановлены с марта 2022 года.

Не подтверждено страницей Microsoft: что `0xC1900500` означает именно региональный отказ, что смена `CountryCode` помогает и что ExecTI безопасен для служебной ветки. Это наблюдение: ответ модератора Microsoft Q&A, сообщения пользователей из России и Беларуси и одинаковый отказ страницы и утилиты. Модераторы форума ссылок на ISO не выдают — [прошлый запрос прямого ISO](/articles/vtoroj-zapret-microsoft-qa-iso/) закончился таким же отказом. VPN не помогает: проверка не сводится к одному IP-адресу.
