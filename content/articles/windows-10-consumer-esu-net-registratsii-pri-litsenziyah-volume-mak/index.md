Если в Windows 10 появилась лицензия ESU канала Volume:MAK, проверьте установленные лицензии параметром `/dlv all`, найдите Activation ID записи ESU и удалите только этот ключ. Microsoft документирует, что устройства с уже имеющейся ESU-лицензией не получают предложение consumer ESU, но не связывает это условие именно с Volume:MAK.

Порядок удаления ESU-лицензии и возврата пункта регистрации Microsoft не документирует, поэтому результат не гарантирован. Команда `slmgr.vbs /upk` без указания Activation ID удаляет ключ текущей редакции Windows; сначала зафиксируйте её активацию и не продолжайте, если не уверены, какой идентификатор относится к ESU.

## Почему Consumer ESU не предлагает регистрацию

Условие программы сформулировано как «устройства, у которых уже есть лицензия ESU», без разделения на потребительскую и корпоративную: для такого устройства регистрация consumer ESU не предлагается. Это не сбой Центра обновления. Microsoft не уточняет, что именно канал Volume:MAK скрывает пункт; такой вывод по одному названию канала делать нельзя.

В корпоративной программе ESU лицензии активируют MAK-ключом, полученным через центр администрирования Microsoft 365, а происхождение ключей после стороннего скрипта по имеющимся данным неизвестно. Ключ MAK выдаётся организации и ставится на каждое устройство отдельно, а активируется командой с Activation ID конкретного года программы, поэтому ESU-лицензия канала Volume:MAK на домашнем компьютере означает, что она пришла не из потребительской программы, где лицензия привязывается к учётной записи Microsoft, и откуда взялся ключ, по документации установить нельзя.

Для consumer ESU нужна Windows 10 версии 22H2 редакции Home, Professional, Pro Education или Workstations. Учётная запись Microsoft для входа должна иметь права администратора и не быть детской; лицензия ESU связывается с этой учётной записью. Если ESU не нужна и вы рассматриваете переход на другую систему, порядок обновления Windows 10 до Windows 11 описан [отдельно](/articles/obnovit-windows-10-do-windows-11-2026-cherez-parametry-i-iso/).

ESU предоставляет критические и важные обновления безопасности, но не новые функции, исправления без безопасности или общую поддержку Windows. Регистрация в consumer ESU привязывает лицензию к учётной записи Microsoft, покрывает до десяти устройств и действует до 12 октября 2027 года, поэтому после снятия чужого ключа имеет смысл сразу пройти официальный мастер, а не откладывать проверку до первого пропущенного обновления безопасности. Сначала выясните, есть ли в системе активная ESU-запись, и не воспринимайте отсутствие регистрации как обычный сбой Центра обновления Windows.

## Как найти Activation ID ESU-лицензии

Откройте командную строку и выполните команду. Она выводит сведения о лицензиях применимых установленных продуктов и не требует прав администратора. Вывод сохраните в текстовом файле: он понадобится для сравнения после удаления.

```cmd
cscript c:\windows\system32\slmgr.vbs /dlv all
```

Найдите запись с названием программы ESU и статусом `Licensed`, затем выпишите её `Activation ID`. Именно этот идентификатор понадобится для удаления ключа конкретного продукта. Идентификаторов в выводе может быть несколько, потому что у программ ESU Year1, Year2 и Year3 они разные, поэтому выписывайте тот, который относится к записи, мешающей регистрации, и сверяйте его с названием программы, а не с последними знаками ключа. Если в выводе рядом с лицензией указано `Volume:MAK`, это согласуется с корпоративным способом активации ESU, но не доказывает, что канал сам по себе вызвал исчезновение пункта.

Отдельно сохраните состояние активации Windows. Команда `/xpr` показывает срок её действия; MAK- и retail-активация бессрочны. По документации именно `/dlv all` служит для получения Activation ID установленных редакций, поэтому не ищите идентификатор в разделе «Активация» и не подставляйте в команду последние пять знаков ключа из вывода `/dlv`.

```cmd
cscript c:\windows\system32\slmgr.vbs /xpr
```

Сверьте результат с разделом **Параметры → Обновление и безопасность → Активация**: там должно быть указано, что Windows активирована, в том числе цифровой лицензией, связанной с учётной записью Microsoft. Не выполняйте удаление, если не можете отличить ESU-запись от записи Windows.

## Снять только ESU-ключ, не задев ключ Windows

В командной строке, запущенной от имени администратора, укажите Activation ID именно ESU-записи. Не оставляйте вместо него угловые скобки: подставьте значение, которое выписали из вывода. Не угадывайте.

```cmd
cscript c:\windows\system32\slmgr.vbs /upk <Activation ID ESU>
```

Параметр Activation ID позволяет выбрать установленный продукт, отличный от текущей редакции Windows. Без него команда удаляет ключ текущей редакции, а после перезагрузки система останется без лицензии, если не установлен новый ключ. Ключ Windows не трогаем. Затем перезагрузите компьютер.

После перезагрузки повторите обе проверки: у ESU-записи не должно оставаться статуса `Licensed`, а `/xpr` должен подтвердить прежнюю активацию Windows. Если `/xpr` показывает прежнюю активацию, а ESU-запись потеряла статус `Licensed`, значит команда сняла ключ указанного продукта, а не текущей редакции Windows, но появление пункта регистрации всё равно зависит от остальных условий программы, которые перечислены ниже в блоке сбоев. Если обнаружилась проблема с тем, что лицензия возвращается после команды, сопоставьте её с описанным [случаем повторного появления лицензии](/articles/stels-hwid/), но не запускайте команды для другой записи наугад.

Откройте **Параметры → Обновление и безопасность → Центр обновления Windows**, нажмите «Проверить наличие обновлений» и проверьте, появился ли пункт регистрации. Он показывается при выполнении требований, однако Microsoft не обещает его возвращение после снятия ESU-ключа. Состояние регистрации проверяется в том же разделе.

## Если ссылка регистрации так и не появилась

- Если после снятия ESU-ключа ссылки нет, проверьте версию 22H2, подходящую редакцию, вход в не детскую учётную запись Microsoft с правами администратора и отсутствие режима киоска, домена Active Directory, Microsoft Entra и MDM: при любом из этих условий регистрация не предлагается.
- Если пакет KB5126256 не установлен или мастер регистрации завершался с ошибкой, установите пакет и все доступные обновления. KB5126256 обновляет компоненты лицензирования и регистрации, но сам устройство не регистрирует, а сбой мастера consumer ESU исправляло внеплановое обновление KB5071959 от 11 ноября 2025 года.
- Если Windows перестала быть активированной, верните законный ключ этой машины командами ниже или через раздел **Параметры → Обновление и безопасность → Активация** и только после этого повторяйте проверки.
- Если ни одна проверка не объяснила проблему, сохраните вывод команд `/dlv all` и `/xpr`, версию и редакцию Windows и обратитесь в поддержку Microsoft. При проблеме с активацией Windows сверяйте канал и состояние лицензии с [разбором ошибки активации](/articles/oshibka-0x8007232b-pri-aktivatsii-windows-10-pro/).

```cmd
cscript c:\windows\system32\slmgr.vbs /ipk <законный ключ этой машины>
cscript c:\windows\system32\slmgr.vbs /ato
```

## Нужна помощь по этой теме

Помогаю разобрать вывод лицензий: покажу, какой Activation ID относится к ESU, а какой — к самой Windows. Такой разбор помог не перепутать записи: сначала сверяем `/dlv all` и `/xpr`, потом решаем, что делать с активацией.

Если пункт регистрации не появился, можно проверить требования consumer ESU и понять, какие данные собрать для диагностики. Для этого используйте кнопку «Чат на сайте»; в сообщении укажите версию Windows и результаты проверок, не присылая ключ продукта.
