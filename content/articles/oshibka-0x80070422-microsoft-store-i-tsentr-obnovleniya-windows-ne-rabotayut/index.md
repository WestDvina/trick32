Ошибка 0x80070422 — системный код 1058, `ERROR_SERVICE_DISABLED`: нужная служба отключена, поэтому Центр обновления Windows и Microsoft Store не могут работать. Исправление — найти отключённую службу, вернуть ей штатный тип запуска, проверить политики, сбросить кэш обновлений, затем восстановить системные компоненты и Store.

Это не ошибка загрузки. Код не называет конкретную службу. Начните с проверки, а не нажимайте «Повторить» и не переустанавливайте Windows.

В коде 0x80070422 часть `0x422` соответствует 1058 — `ERROR_SERVICE_DISABLED`. Справочник Центра обновления Windows описывает это как случай, когда служба «перестала работать или не работает». По одному коду нельзя определить, какая именно служба отключена; это выясняется проверкой.

0x80070005 — отдельная ошибка: код 5 `ERROR_ACCESS_DENIED`, то есть отказано в доступе. Она не исправляется изменением типа запуска службы. Если после починки служб остаётся 0x80070005, проверяйте доступ и политики, а не меняйте типы запуска повторно. Когда оба кода пришли вместе, начинают со служб: пока они отключены, остальные проверки всё равно не дадут результата.

## Найдите службу, которую отключили

Откройте Терминал или PowerShell от имени администратора. Команда покажет тип запуска служб, от которых зависят обновление и установка приложений; ищите `Disabled` в столбце `StartType`.

```powershell
Get-Service -Name wuauserv,bits,cryptsvc,trustedinstaller,dosvc,usosvc,installservice |
  Select-Object Name, Status, StartType
```

Для `wuauserv` и `bits` проверьте подробный тип запуска. `START_TYPE : 4 DISABLED` означает, что служба отключена: значение 4 в конфигурации службы — это `SERVICE_DISABLED`, и запуск такой службы возвращает `ERROR_SERVICE_DISABLED`. Блок `DEPENDENCIES` показывает связанные с ней службы.

```cmd
sc qc wuauserv
sc qc bits
```

Затем проверьте три ветви политик. Ключи могут содержать и другие параметры, поэтому важно увидеть значения целиком; `/s` показывает вложенные значения.

```cmd
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate" /s
reg query "HKLM\SOFTWARE\Policies\Microsoft\WindowsStore" /s
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\SystemRestore" /s
```

Ищите `SetDisableUXWUAccess`, `RemoveWindowsStore` и `DisableSR`: они могут закрывать доступ к обновлениям, Store и восстановлению системы. Если `reg query` отвечает, что раздел не найден, политики нет — переходите к исправлению типа запуска.

## Верните тип запуска и снимите блокировки

Команды ниже возвращают типы запуска по умолчанию из справки Microsoft — ручной для служб обновления и установки, автоматический для криптографической службы и оптимизации доставки, — но сама справка относится к фиксированным устройствам Windows IoT, поэтому эти значения здесь служат ориентиром для восстановления отключённых служб, а не разрешением отключать обновления на домашнем компьютере. Запустите команды в консоли администратора; пробел после `start=` обязателен.

```cmd
sc.exe config wuauserv start= demand
sc.exe config bits start= demand
sc.exe config cryptsvc start= auto
sc.exe config dosvc start= auto
sc.exe config usosvc start= demand
sc.exe config trustedinstaller start= demand
sc.exe config installservice start= demand
```

Удалите только найденные значения, а не целые ключи: в ветвях могут находиться другие настройки. Если команда сообщает, что значение не найдено, пропустите его — такой политики нет.

```cmd
reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate" /v SetDisableUXWUAccess /f
reg delete "HKLM\SOFTWARE\Policies\Microsoft\WindowsStore" /v RemoveWindowsStore /f
reg delete "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\SystemRestore" /v DisableSR /f
```

После изменения настроек повторно проверьте `Get-Service` и `sc qc`: вместо `DISABLED` должен отображаться ручной или автоматический тип запуска.

## Сбросьте кэш обновлений и верните Store

Затем остановите службы обновления, удалите кэш и запустите службы снова, но перед этим оговорка: это сочетание двух вариантов из справки Microsoft, где быстрый сброс удаляет `SoftwareDistribution`, а агрессивный переименовывает `catroot2` в `.bak` и сохраняет прежнюю папку, чтобы её можно было вернуть, — новую Windows создаст сама.

```cmd
net stop bits
net stop wuauserv
net stop cryptsvc
rd /s /q %systemroot%\SoftwareDistribution
ren %Systemroot%\System32\catroot2 catroot2.bak
net start cryptsvc
net start bits
net start wuauserv
```

Если `catroot2.bak` от прошлой попытки уже существует, сначала переименуйте её, иначе команда `ren` не выполнится.

Проверьте образ Windows, затем защищённые системные файлы. Порядок DISM → SFC — последовательность этого плана, а не отдельное требование Microsoft; обе команды запускайте с правами администратора.

```cmd
DISM /Online /Cleanup-Image /RestoreHealth
sfc /scannow
```

Пакет Store сначала проверяют у своего пользователя, а если его нет — у всех пользователей, и эта проверка идёт из PowerShell с повышенными правами. Перерегистрацию и сброс, наоборот, выполняют без прав администратора: иначе Store зарегистрируется учётной записи администратора вместо вашей.

```powershell
Get-AppxPackage *Microsoft.WindowsStore*
```

```powershell
Get-AppxPackage *Microsoft.WindowsStore* -AllUsers
```

Если пакет существует, зарегистрируйте его для своего пользователя.

```powershell
Add-AppxPackage -RegisterByFamilyName -MainPackage Microsoft.WindowsStore_8wekyb3d8bbwe
```

Если приложение всё ещё не запускается, сбросьте его настройки; команда не удаляет Store.

```powershell
Get-AppxPackage *Microsoft.WindowsStore* | Reset-AppxPackage
```

После этого перезагрузите компьютер и проверьте Центр обновления и установку приложения из Store. Store для установки и обновления приложений обращается к конечным точкам Центра обновления Windows, поэтому блокировка обновлений закрывает доступ и ему. Полное удаление Store не поддерживается: Microsoft называет поддерживаемым вариантом сброс или переустановку операционной системы, а на практике сначала пробуют обновление на месте с установочного носителя.

## Если ошибка возвращается

- Если `sc qc` снова показывает `DISABLED` — проверьте политики ещё раз и посмотрите, не переключил ли тип запуска обратно другой компонент, например служба `WaaSMedicSvc`; официального описания такого поведения у Microsoft нет, это наблюдение.
- Если обновление после исправления служб по-прежнему завершается с `0x80070005` — проверяйте доступ и политики; тип запуска больше не меняйте.
- Если DISM сообщает, что не может найти источник восстановления — укажите доступный источник восстановления, потому что без файлов из образа эта проверка образ не починит и вернёт тот же отказ.
- Если пакета Microsoft Store нет или перерегистрация не помогла — используйте обновление Windows на месте с установочного носителя: оно сохраняет файлы и приложения, тогда как [сброс](/articles/sbros-windows-do-zavodskih-nastroek/) и чистая установка удаляют приложения и настройки, а вариант с удалением всего стирает и личные файлы. Носителя под рукой может не быть, и тогда выручает [переустановка без флешки](/articles/windows-11-pereustanovka-bez-fleshki-cloud-rebuild/), но результат у неё тот же.

На сборке с вырезанными компонентами нужные службы могут отсутствовать в реестре, а DISM — не найти файлы для восстановления. По наблюдениям, в таком случае правка типов запуска не помогает; переход к установочному носителю — запасной путь, а не гарантия ремонта.
