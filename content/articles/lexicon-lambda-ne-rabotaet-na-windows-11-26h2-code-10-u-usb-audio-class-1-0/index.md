Карта Lexicon Lambda перестала работать после перехода на Windows 11 26H2 — так описывает свой случай пользователь Microsoft Q&A. В Диспетчере устройств жёлтый треугольник, внутри — «Запуск этого устройства невозможен (код 10)». Звука нет. ASIO-драйвер карту не видит.

Судя по описанию, это не поломка конкретной карты. Microsoft признала проблему целого класса USB Audio Class 1.0 и держит её в списке известных. Но статус записи — Mitigated, а не Resolved. Проще говоря: часть симптомов закрыли, а Code 10 в known issues остался.

## Что Microsoft уже признала

В release health Windows 11 26H2 есть отдельный пункт «USB audio devices might fail to start or produce no sound». Проблема открыта 11 сентября 2026 года, последнее обновление записи — 29 сентября. Статус Mitigated.

Симптомы Microsoft перечисляет прямо:

- в Диспетчере устройств устройство показывает «This device cannot start (Code 10)»;
- нет вывода звука;
- регуляторы громкости не отвечают или стоят на нуле;
- настройки звука не отвечают или недоступны.

И главное ограничение: «This issue is limited to USB Audio Class 1.0 devices». То есть страдают не все звуковые карты, а устройства, которые работают по старому классу USB Audio. Судя по описанию в Q&A, Lexicon Lambda относится именно к этому классу.

Дальше Microsoft пишет, что работает над исправлением в будущем обновлении Windows. Сроков не называет. Для немедленного обходного решения отправляет IT-администраторов в Microsoft Support for Business. Пользовательского рецепта в записи нет.

На 3 ноября 2026 года статус всё ещё Mitigated.

## Mitigated — не значит исправлено

Хронология здесь важнее любого пересказа.

8 сентября 2026 года выходит KB5124008 для Windows 11 24H2 и 25H2. В known issues появляется тот самый пункт про USB-аудио: Code 10, нет звука, громкость не регулируется.

14 сентября выходит внеплановое KB5129195 для Windows 11 25H2 и 24H2, сборки 26200.9457 и 26100.9457. Оно исправляет часть проблемы. Дословно: «Some USB Audio Class 1.0 devices functioning as expected in standard stereo configurations failed when using multichannel audio features, including 8-channel or 3D audio modes».

Проще говоря, KB5129195 вернул звук части таких устройств — тем, у кого карта работала в стерео, но падала в 8-канальном или 3D-режиме.

При этом внеплановое обновление не устраняло ошибку запуска в обычном стереорежиме, из-за которой устройство остаётся с жёлтым треугольником и кодом 10 в Диспетчере устройств, не даёт вывода звука и не открывает ASIO-драйвер даже после установки обновления. И там же Microsoft честно оговаривает: «There are other audio symptoms not resolved in this OOB update».

В списке известных проблем самого KB5129195 остаётся пункт «USB Audio Class 1.0 devices with error Code 10 or no output». То есть ошибка запуска никуда не делась.

Дальше ничего не меняется. Внеплановое KB5134133 от 26 октября и предпросмотр KB5127936 от 28 октября снова содержат в известных проблемах пункт про USB-аудио с Code 10. 28 октября 26H2 стала доступна всем подходящим устройствам — вместе с нерешённой аудиопроблемой.

Вывод неприятный, но точный: на конец октября 2026 года полного исправления для стереоустройства Class 1.0 с Code 10 не выпущено.

## Как проверить, что у вас тот же случай

Сначала посмотрите код ошибки. Откройте Диспетчер устройств, найдите звуковую карту, откройте свойства. Нужна строка «This device cannot start (Code 10)» или её русский вариант «Запуск этого устройства невозможен (код 10)».

Потом проверьте, что в ошибке именно звуковое устройство, а не что-то рядом. В PowerShell от администратора:

```powershell
Get-PnpDevice -Class MEDIA -PresentOnly -Status ERROR,DEGRADED,UNKNOWN
```

Команда документирована Microsoft и показывает присутствующие устройства класса MEDIA со статусом ошибки, деградации или неизвестным. Если в списке только ваша карта — картина сходится.

Уточнить класс и код проблемы можно так:

```powershell
Get-PnpDevice -Class MEDIA | Format-List Status,Problem,FriendlyName,InstanceId
```

В поле `Problem` у проблемного устройства будет `10`. Это тот же Code 10, только без текста. Свойство приходит из WMI-класса Win32_PnPEntity и в документации самого командлета не описано — если поле пустое, код смотрите на вкладке «Общие» в свойствах устройства.

Теперь проверьте драйвер. Для USB Audio Class 1.0 Windows сама загружает системный `usbaudio.sys`. Если устройство опознаётся как USB Audio-совместимое, поставщик драйвера — Microsoft, а не Lexicon. Так и должно быть: по документации Microsoft такое устройство не требует проприетарного драйвера-адаптера.

И последнее: убедитесь, что система действительно 26H2. `winver` покажет версию и сборку без похода в параметры.

## Почему драйвер Lexicon и ASIO не лечат

Справочник Microsoft по кодам Диспетчера устройств на Code 10 даёт стандартный совет: обновить драйвер. Для обычного сбоя это правильно. Здесь совет упирается в устройство самого стека.

USB-карту класса 1.0 обслуживает системный `usbaudio.sys`. ASIO-драйвер v2.7, судя по описанию пользователя, карту не видит: пока системный драйвер не запускает устройство, открывать ASIO нечего. Это объяснение, а не цитата Microsoft.

В описанном случае ни переустановка драйвера Lexicon, ни перерегистрация DLL, ни перезапуск Audiosrv с AudioEndpointBuilder результата не дали. Логика подсказывает, что ошибка возникает на уровне системного драйвера, а не в вендорском пакете.

Код 10 у аудиоустройства вообще бывает разным: иногда виноват универсальный драйвер, который подхватил не то устройство, и тогда помогает возврат правильного пакета — [как в случае с HDMI-аудио после Driver Booster](/articles/kod-10-audio-hdmi-ne-tot-drayver/). В нашем случае другой уровень: не драйвер карты, а известная ошибка Windows.

## Что делать, пока исправления нет

**1. Поставьте последнее доступное накопительное обновление.** На 28 октября это предпросмотр KB5127936 или более новое. Скачайте его через Центр обновления Windows: Settings → Windows Update → Check for updates. Если обновление не приходит, найдите нужный KB по номеру в каталоге Microsoft Update Catalog и установите вручную. После установки перезагрузитесь и проверьте карту снова. Но не ждите чуда: KB5127936 сам ещё содержит Code 10 в известных проблемах. Обновление нужно, чтобы не пропустить момент, когда исправление выйдет.

**2. Если карта работает в стерео, но падает в многоканальном режиме — попробуйте 2-канальный режим.** Microsoft в статьях KB5124008 и KB5129195 для 25H2 и 24H2 пишет, что части пользователей это возвращало звук. KB5129195 закрывает 8-канальный и 3D-режим, но применяется к 25H2 и 24H2. Прямого указания для 26H2 в документации нет: там своя ветка сборок.

**3. Если Code 10 в обычном стерео — пользовательского обходного пути нет.** Microsoft предлагает ждать будущего обновления. Если звук нужен сразу, подключите другое аудиоустройство: по документации Microsoft проблема ограничена USB Audio Class 1.0, поэтому карта другого класса или устройство с собственным драйвером производителя — временный выход. Организациям с немедленной потребностью — Support for Business. На домашнем ПК остаётся периодически проверять release health.

**4. Не пытайтесь удалить KB5124008 на 26H2.** Статья KB5124008 относится к 24H2 и 25H2; в 26H2 его изменения входят кумулятивно, но исправления Code 10 там нет — он остаётся в known issues и в KB5127936 от 28 октября. Пользователь из Q&A сообщает, что `wusa` удалить обновление не дала. Это его наблюдение, а не инструкция Microsoft.

**5. Не рассчитывайте на откат системы как на план.** Кнопка «Назад» доступна ограниченное время и не всегда. Как вернуться на 25H2 или 24H2, если откат ещё открыт, разобрано в материале [об удалении 26H2](/articles/kak-udalit-windows-11-26h2-i-vernutsya-na-25h2-24h2/). Но это возврат к системе без исправления, а не лечение Code 10.

**6. Проверьте карту на другой машине, где она работала раньше.** Если и там Code 10, это не доказывает поломку карты: проблема документирована не только для 26H2, но и для 24H2, 25H2 и других версий. Зато тест отделяет вашу карту от системной ошибки, если на другой машине она запускается.

## Чего не делать

Не лезьте в реестр за «правильными» параметрами USB-аудио. Microsoft не публиковала для этой проблемы ни ключей, ни значений. Всё, что найдётся в чужих советах, — догадки.

Не отключайте проверку подписи драйверов и не подсовывайте старые пакеты USBAudio из сторонних сборок. Это лечит другую болезнь и добавляет новую.

Не считайте `STATUS_DEVICE_DATA_ERROR` отдельным кодом Microsoft для этой истории. В release health такого кода нет: он пришёл из описания пользователя в Q&A. Для Microsoft симптом называется Code 10.

И не покупайте новую карту, пока не проверили её на другой системе. Известная проблема класса не делает вашу конкретную карту мёртвой.

## Что подтверждено, а что нет

Подтверждено страницами Microsoft: проблема USB Audio Class 1.0 с Code 10 существует, статус — Mitigated, симптомы и ограничение по классу устройств совпадают с описанными, KB5129195 закрыл только многоканальную часть, а на 28 октября Code 10 всё ещё в известных проблемах.

Не подтверждено: что проблема воспроизводится именно на Lexicon Lambda — конкретная модель в документации Microsoft не названа, речь только о классе устройств. Не подтверждены причина, срок исправления и пользовательский обходной путь. Нет и официального подтверждения, что KB5129195 помогает на 26H2: в его статье указаны 25H2 и 24H2.

На момент публикации Microsoft проблему официально признала, но полностью не исправила. Любой совет «удалите обновление и всё заработает» на 26H2 — гадание.
