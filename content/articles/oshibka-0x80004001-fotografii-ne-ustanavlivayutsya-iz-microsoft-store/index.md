«Фотографии» не устанавливаются и выдают **0x80004001**. В этом случае причина не в самом приложении: Microsoft Store отсутствует в системе, а отдельной поддерживаемой переустановки Store нет. Без потери данных остаётся обновление Windows с параметром `setup.exe /auto upgrade`.

Если у вас Store на месте, а «Фотографии» всё равно не ставятся, начните с перерегистрации пакета — этот путь ниже.

`0x80004001` — общий HRESULT `E_NOTIMPL`, «Not implemented». Это код COM, а не отдельная ошибка Microsoft Store. Он не называет ни повреждённый пакет, ни службу, ни обновление, поэтому начинать нужно с проверки пакета и журнала развёртывания.

## Проверьте, остался ли Store

Откройте обычное окно PowerShell и запросите пакет для текущего пользователя:

```powershell
Get-AppxPackage *Microsoft.WindowsStore*
Get-AppxPackage *Microsoft.WindowsPhotos*
```

В выводе важны `PackageFullName`, `InstallLocation` и `Status`. Пустой результат по Store означает, что пакет не найден для текущего пользователя. Это ещё не проверка всех учётных записей.

Чтобы посмотреть пакеты всех пользователей, откройте PowerShell с повышенными правами:

```powershell
Get-AppxPackage *Microsoft.WindowsStore* -AllUsers
```

Команда только читает список. Если и здесь пусто, перерегистрировать нечего: переходите к восстановлению Windows обновлением.

Если пакет найден, его можно попробовать перерегистрировать. Это вспомогательный шаг, а не замена восстановлению, когда Store отсутствует. Выполняйте в обычном PowerShell, без повышения прав:

```powershell
Add-AppxPackage -RegisterByFamilyName -MainPackage Microsoft.WindowsStore_8wekyb3d8bbwe
```

Если в выводе есть `InstallLocation`, зарегистрируйте манифест из папки пакета. Вместо `<пакет>` подставьте фактическое имя папки:

```powershell
Add-AppxPackage -Path "C:\Program Files\WindowsApps\<пакет>\AppxManifest.xml" -Register -DisableDevelopmentMode
```

Если после этого Store установлен, но не открывается, попробуйте сбросить кэш командой без ключей:

```cmd
wsreset.exe
```

В ответах Q&A встречается вариант `wsreset -i`. Microsoft документирует только сброс кэша, поэтому `-i` — неофициальная попытка: она может помочь, когда пакет установлен, но отсутствующий Store не вернёт.

Теперь посмотрите журнал развёртывания и состояние служб:

```powershell
Get-WinEvent -LogName "Microsoft-Windows-AppXDeploymentServer/Operational" -MaxEvents 40 |
  Format-Table TimeCreated, Id, LevelDisplayName, Message -Wrap
Get-Service AppXSvc, ClipSVC, StateRepository | Format-Table Name, Status, StartType
```

В записи с `0x80004001` прочитайте время, идентификатор и сообщение целиком: они покажут операцию, на которой остановилось развёртывание. `AppXSvc`, `ClipSVC` и `StateRepository` штатно работают в режиме `Manual` и запускаются по требованию. Если у `AppXSvc` стоит `Start=2`, это не исправление и не объясняет ошибку. `Disabled` зафиксируйте, но не меняйте тип запуска наугад.

Если пакет найден, но развёртывание падает с ошибкой, проверьте хранилище компонентов и системные файлы в повышенной командной строке:

```cmd
DISM /Online /Cleanup-Image /ScanHealth
DISM /Online /Cleanup-Image /RestoreHealth
sfc /scannow
```

DISM идёт первым: он восстанавливает хранилище, из которого SFC берёт файлы для замены повреждённых. По умолчанию `/RestoreHealth` использует Центр обновления Windows; если он не работает, понадобятся `/Source` и `/LimitAccess`. Подробнее о такой ситуации — в [разборе ошибки 0x80073712](/articles/windows-error-0x80073712/).

## Запустите восстановление обновлением

Когда `Get-AppxPackage` не находит Store ни у текущего пользователя, ни через `-AllUsers`, перерегистрировать нечего. Запустите `setup.exe` из распакованного установочного носителя в повышенной командной строке:

```cmd
setup.exe /auto upgrade
```

Параметр `/auto upgrade` выполняет обновление Windows и сохраняет приложения и данные. С Windows 11 22H2 носитель должен совпадать по языку интерфейса с целевым устройством. Подготовка ISO описана в [материале об обновлении Windows через ISO](/articles/obnovit-windows-10-do-windows-11-2026-cherez-parametry-i-iso/).

После завершения проверьте `Get-AppxPackage *Microsoft.WindowsStore*` и установите «Фотографии» из Store. Гарантии, что пропавший Store появится после обновления, страницы Microsoft не дают. Если пакета по-прежнему нет, остаётся сброс Windows или переустановка ОС.

## Если шаги не сработали

- **Если запрос пакета Store ничего не вывел** — проверьте результат с `-AllUsers`. Если пакет отсутствует, переходите к восстановлению обновлением, а не к правке служб.
- **Если `Add-AppxPackage` завершился ошибкой** — сохраните полный текст и снова посмотрите событие с `0x80004001` в журнале `Microsoft-Windows-AppXDeploymentServer/Operational`.
- **Если DISM не может скачать файлы** — проверьте работу Центра обновления Windows; без источника восстановление хранилища не завершится.
- **Если после `setup /auto upgrade` Store не появился** — проверьте пакет ещё раз; поддерживаемого отдельного восстановления Store нет, остаётся сброс или переустановка ОС.
