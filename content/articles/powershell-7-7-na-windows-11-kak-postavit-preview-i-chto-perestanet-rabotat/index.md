PowerShell 7.7 доступна только как preview-сборка: Microsoft официально её не поддерживает, MSI-пакета для неё нет, а winget ставит MSIX, в котором не будет remoting и записи в `$PSHOME`.

Ставить её можно рядом с рабочей LTS-версией 7.6.6. Рабочую установку она не заменяет.

## Почему у 7.7 нет обычного установщика

Ветка 7.7 существует как preview, а не как поддерживаемый выпуск. Microsoft отдельно предупреждает, что preview-сборки официально не поддерживаются и не предназначены для продакшена. Поэтому её разумно рассматривать как отдельную среду для проверки, а не переносить на неё задачи, от которых зависит работа.

Начиная с релиза 7.7.0 MSI-пакета нет. Только MSIX. Это отличается от привычной схемы предыдущих выпусков: начиная с пакета 7.6.0 WinGet и так выбирает MSIX по умолчанию, а MSI для тех пакетов требовал явного выбора типа установщика. У 7.7 такого MSI-варианта уже нет.

7.7 собрана на .NET 11, а текущая LTS-ветка — PowerShell 7.6.6. Это две разные ветки по назначению: первая остаётся preview, вторая — рабочей LTS. PowerShell 7 устанавливается отдельно и не заменяет Windows PowerShell 5.1, поэтому наличие старой версии само по себе не мешает установить новую.

На момент проверки страницы Microsoft расходятся в номере preview: в жизненном цикле названа одна сборка, а на страницах установки и нововведений — другая. Поэтому ниже речь о preview-сборке 7.7 без привязки к номеру. В Windows 11 проверьте доступность WinGet:

```powershell
winget --version
```

WinGet входит в Windows 11 как часть App Installer, поэтому отдельный установщик для него не нужен.

## Как поставить preview рядом с рабочей версией

Сначала проверьте, что запускается сейчас. Выполните команды в открытом окне PowerShell: `$PSHOME` покажет каталог активной установки, а `$PSVersionTable.PSVersion` — её версию.

```powershell
$PSHOME
$PSVersionTable.PSVersion
```

Путь помогает определить тип пакета. Каталог `$Env:ProgramFiles\WindowsApps\...` означает MSIX; `$Env:ProgramFiles\PowerShell\7` — скорее всего MSI-установка, её стоит подтвердить в списке установленных программ; `$HOME\.dotnet\tools` указывает на глобальный инструмент .NET. Если путь другой, это не один из этих вариантов. Для preview, установленной через WinGet, ожидайте путь внутри WindowsApps: с 7.7.0 WinGet ставит только MSIX, а такой пакет распаковывается в защищённый каталог приложения, который и показывает `$PSHOME` в запущенном окне.

Запустите установку preview одной командой:

```powershell
winget install --id Microsoft.PowerShell.Preview --source winget
```

После завершения откройте новое окно `pwsh` и повторите обе команды. Новое окно обязательно. Уже открытый процесс продолжает работать с прежней версией, а профиль Windows Terminal сам не переключается: [Intelligent Terminal](/articles/intelligent-terminal-windows-ai/) ставится отдельным приложением и тоже ничего не меняет в текущем окне.

Для рабочей LTS-ветки нужен другой пакет — PowerShell без суффикса Preview. Если ваши скрипты используют remoting или пишут в `$PSHOME`, ставьте его MSI-пакетом и указывайте тип установщика явно:

```powershell
winget install --id Microsoft.PowerShell --source winget --installer-type wix
```

Без `--installer-type wix` WinGet с пакета 7.6.0 по умолчанию ставит MSIX, и тогда ограничения песочницы будут и у рабочей версии тоже. Это LTS 7.6.6.

Preview ставится рядом со стабильной версией: новая preview заменяет предыдущую preview, а не рабочую установку. Поэтому ярлык ничего не решает — открывайте тот `pwsh`, где будете работать, и сверяйте `$PSHOME` в этом окне. Иначе ошибка выяснится на середине задачи, на команде, которой в MSIX-версии нет. Пункт запуска в Проводнике настраивается отдельно: [страница «Контекстное меню» в «Параметрах»](/articles/kontekstnoe-menyu-windows-11-nastrojka/) показывает, какие пункты можно убрать.

## Что не заработает в MSIX-версии

MSIX работает в песочнице приложения: она блокирует изменения корневой папки, а `$PSHOME` лежит внутри этой области. Ограничение привязано к пакету, а не к окну, поэтому его не снимет ни новое окно, ни переустановка preview.

В первую очередь это касается четырёх групп функций:

- PowerShell remoting не поддерживается; конфигурация WSMan также требует изменений, которые песочница блокирует.
- Нельзя создавать и редактировать профили `$PROFILE.AllUsersAllHosts` и `$PROFILE.AllUsersCurrentHost`: оба должны храниться в `$PSHOME`.
- Не поддерживаются команды, которым нужна запись в `$PSHOME`: `Register-PSSessionConfiguration`, `Update-Help -Scope AllUsers`, `Enable-ExperimentalFeature -Scope AllUsers` и `Set-ExecutionPolicy -Scope LocalMachine`.
- Не получится менять системные настройки, которые хранятся в `$PSHOME`.

Обычные сеансы, скрипты и пользовательские профили остаются доступны; поддерживаются также исходящие подключения по SSH, поэтому для задач, где нужен только запуск скриптов и работа с файлами на этой машине, MSIX-версия подходит без оговорок, а ограничения начинаются там, где скрипт требует remoting, правки общесистемных настроек или профиля для всех пользователей.

Для снятия виртуализации файлов и реестра у MSIX требуется Windows build 1903 или новее. Это условие именно для такого поведения MSIX, а не требование PowerShell 7.7. На Windows 11 условие выполняется. Не используйте 1903 как минимальную версию Windows для самой PowerShell.

## Если preview мешает или обновление приходит не то

- Если нужен PowerShell remoting или `Set-ExecutionPolicy -Scope LocalMachine`, проверьте, каким пакетом ставилась рабочая версия: при установке через WinGet с 7.6.0 это тоже MSIX, и ограничения у неё те же. Для таких задач нужна MSI-установка: `winget install --id Microsoft.PowerShell --source winget --installer-type wix`. Preview — для проверки.
- Если `winget upgrade --id Microsoft.PowerShell` обновил не ту ветку, проверьте идентификатор пакета: `Microsoft.PowerShell` относится к стабильной ветке, а preview устанавливается отдельным пакетом `Microsoft.PowerShell.Preview`.
- Если после установки запускается не тот `pwsh`, выполните `$PSHOME` и `$PSVersionTable.PSVersion` именно в этом окне, затем проверьте выбранный профиль или ярлык запуска. У preview и рабочей ветки отдельные пакеты, так что один лишь факт установки не определяет, какой процесс открыт.
- Если в preview нет нужного поведения, не считайте это подтверждением поломки системы: это предварительная сборка, и часть поведения в ней ещё меняется. Сверьте, какую ветку и пакет вы запустили, прежде чем менять рабочую установку.

## Нужна помощь с PowerShell на Windows 11?

Я помогу проверить, какой `pwsh` запускается, и разобраться, почему MSIX не сохраняет настройки в `$PSHOME` или не даёт подключиться по remoting. По этим вопросам можно написать в чат на сайте.

Опишите, что именно не работает, и приложите вывод `$PSHOME` и `$PSVersionTable.PSVersion` из проблемного окна. Так будет понятно, какая установка запущена и где проходит её ограничение.
