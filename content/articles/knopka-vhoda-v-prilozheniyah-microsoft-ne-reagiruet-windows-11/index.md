В Центре отзывов, Xbox и пасьянсе Solitaire кнопка «Вход» молчит. Окно не открывается. Ошибки тоже нет. Такой симптом описал пользователь на Windows 11 26H1, сборке 28000.3501 (KB5132059), и сброс с повторной установкой приложений ему не помогли, хотя Microsoft эту версию с проблемой не связывает.

Окно входа рисует системный брокер Windows — Web Account Manager (WAM), а не само приложение. Поэтому нажимать «Исправить» и «Сбросить» дальше бессмысленно: перерегистрируйте пакет входа, который соответствует типу учетной записи — `Microsoft.Windows.CloudExperienceHost` (Live ID) для личной и `Microsoft.AAD.BrokerPlugin` для рабочей или учебной. Перерегистрация — документированный Microsoft способ для Microsoft 365 и Outlook, но не отдельная инструкция для Центра отзывов, Xbox и пасьянса: результат не гарантирован.

## Почему сброс приложения не изменил вход

Приложение передаёт запрос на вход системному брокеру WAM. Он отвечает за аутентификацию и работу с учетными записями; пакет самого приложения и пакет входа — разные компоненты. Поэтому сброс приложения не перерегистрирует пакет брокера, который находится отдельно. Сброс и переустановка работают с пакетом самого приложения; пакет входа лежит отдельно, в папке SystemApps, и в эти операции не входит, поэтому нажатие на «Вход» после сброса даёт тот же результат — окно не появляется, ошибки на экране нет. Это объяснение по устройству пакетов, отдельной формулировки у Microsoft для него нет.

Microsoft описывает похожий отказ аутентификации в приложениях Microsoft 365 и Outlook: вход не проходит без действий пользователя, если отсутствуют сведения о пакете ADAL или Live ID. Это не подтверждает отдельно причину для трёх приложений из симптома, но объясняет, почему восстановление их собственных пакетов могло ничего не изменить. Сбой входа бывает и в другом сценарии — например, когда [Windows не принимает верный пароль учетной записи](/articles/windows-11-nevernyj-parol-pri-vernom-parole/).

В справке Microsoft по приложениям из Microsoft Store сброс и повторная установка стоят в самом конце списка действий, поэтому повторять их нет смысла: сначала определите, какая учетная запись используется, затем проверьте соответствующий пакет входа и только после этого переходите к командам, которые регистрируют манифест заново.

## Как выбрать пакет для своей учетной записи

Откройте **Параметры → Учётные записи → Ваши сведения** и определите тип учетной записи. Для личной учетной записи Microsoft, например с адресом `@outlook.com` или `@hotmail.com`, нужен пакет Live ID `Microsoft.Windows.CloudExperienceHost`. Для рабочей или учебной учетной записи нужен `Microsoft.AAD.BrokerPlugin` — плагин Microsoft Entra для WAM. Если с самой учетной записью возникла проблема при создании, это отдельный случай: [создание учетной записи Microsoft может быть заблокировано](/articles/microsoft-account-creation-blocked-october-2026/).

Проверьте наличие обоих пакетов в PowerShell. Команда выводит сведения о пакетах, установленных в текущем профиле. Смотрите на `Name`, `Version` и `InstallLocation`; пустой результат для нужного пакета означает, что он не найден. Целостность пакета это не проверяет.

```powershell
Get-AppxPackage Microsoft.Windows.CloudExperienceHost
Get-AppxPackage Microsoft.AAD.BrokerPlugin
```

Не выбирайте пакет только по совету для другого типа учетной записи: перерегистрация `Microsoft.AAD.BrokerPlugin` не заменяет пакет Live ID для личной учетной записи, и если выполнить обе команды подряд «на всякий случай», вы потратите время на перезапуск приложений и повторные попытки входа, так и не узнав, какое звено сломано.

## Как перерегистрировать пакет и проверить вход

Запустите PowerShell от имени администратора. Выполните только команду для своего типа учетной записи: первая проверяет пакет личной учетной записи, вторая — рабочей или учебной. Если пакет отсутствует, команда регистрирует его манифест из папки SystemApps, а затем снова выводит сведения о пакете.

Для личной учетной записи:

```powershell
if (-not (Get-AppxPackage Microsoft.Windows.CloudExperienceHost)) { Add-AppxPackage -Register "$env:windir\SystemApps\Microsoft.Windows.CloudExperienceHost_cw5n1h2txyewy\Appxmanifest.xml" -DisableDevelopmentMode -ForceApplicationShutdown } Get-AppxPackage Microsoft.Windows.CloudExperienceHost
```

Для рабочей или учебной учетной записи:

```powershell
if (-not (Get-AppxPackage Microsoft.AAD.BrokerPlugin)) { Add-AppxPackage -Register "$env:windir\SystemApps\Microsoft.AAD.BrokerPlugin_cw5n1h2txyewy\Appxmanifest.xml" -DisableDevelopmentMode -ForceApplicationShutdown } Get-AppxPackage Microsoft.AAD.BrokerPlugin
```

Обе команды приведены целиком, как на странице Microsoft: параметры `-DisableDevelopmentMode` и `-ForceApplicationShutdown` входят в неё, сокращать их не нужно.

Пакеты из папки SystemApps принадлежат самой Windows, поэтому их перерегистрация не устанавливает ничего нового и не скачивает файлы из интернета: команда заново читает манифест, который уже лежит на диске, и возвращает системе сведения о пакете, но если сам файл манифеста повреждён или папка недоступна, ошибка повторится и после перезагрузки.

Условие в команде срабатывает только тогда, когда пакета нет. Если `Get-AppxPackage` уже выводит пакет с именем и версией, перерегистрации не произойдёт — команда лишь покажет текущее состояние. Отдельного документированного шага для установленного, но повреждённого пакета входа у Microsoft нет: в этом случае переходите к проверке `Microsoft.AccountsControl`, службы `wlidsvc` и политики.

Команда не мгновенная. Дождитесь её завершения: индикатор прогресса или строка состояния установки допустимы, но важно, чтобы команда закончилась без ошибки и вывела пакет с именем и версией, а ошибка доступа или сообщение об отсутствующем пути означают, что манифест не зарегистрирован и текст ошибки нужно записать, а не повторять команду вслепую.

Две команды нужны потому, что Microsoft развела их по типу учетной записи: пакет Live ID обслуживает личные адреса вроде `@outlook.com` и `@hotmail.com`, а плагин Entra — рабочие и учебные, и если перепутать, система зарегистрирует исправный пакет, который ваша учетная запись всё равно не использует, поэтому вход останется молчащим, а вывод команды при этом будет выглядеть успешным.

Полностью закройте приложение, откройте его снова и проверьте кнопку «Вход» в Центре отзывов. Этот способ Microsoft документирует для приложений Microsoft 365 версии 1807 и новее на Windows 10 1703 и новее; для Центра отзывов, Xbox и пасьянса он не описан отдельно и не гарантирует результат. Перерегистрация затрагивает системный пакет и требует прав администратора.

## Если окно выбора учетной записи не появляется

Если после перерегистрации окна всё ещё нет, проверьте компонент выбора учетной записи `Microsoft.AccountsControl`. Microsoft описывает случай, когда этот компонент перестаёт открываться, и предлагает перерегистрировать его из терминала с правами администратора:

```powershell
if (-not (Get-AppxPackage Microsoft.AccountsControl)) { Add-AppxPackage -Register "$env:windir\SystemApps\Microsoft.AccountsControl_cw5n1h2txyewy\AppxManifest.xml" -DisableDevelopmentMode -ForceApplicationShutdown } Get-AppxPackage Microsoft.AccountsControl
```

Затем проверьте службу `wlidsvc` — Microsoft Account Sign-in Assistant: без неё вход с учетной записью Microsoft не работает. `STOPPED` при `Start` = 3 — норма, служба запускается по требованию; намеренное отключение видно по `Start` = 4, так её выключает политика `AllowMicrosoftAccountSignInAssistant` или ручная правка реестра. Падение при старте показывают события Service Control Manager, а ненулевой `WIN32_EXIT_B` называет код отказа в выводе `sc query`.

```cmd
sc query wlidsvc
```

Тип запуска указан в параметре `Start` службы: `3` означает ручной запуск, `4` — отключённую службу. Если там `4` и отключение не требуется, верните ручной запуск и запустите службу — эти две команды выполняются в PowerShell от имени администратора. В команде `sc config` после `start=` обязателен пробел.

```powershell
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\wlidsvc' -Name Start
```

```cmd
sc config wlidsvc start= demand
```

```powershell
Start-Service wlidsvc
```

Проверьте и политику `EnterpriseDeviceAuthOnly`: она лежит в ветке HKLM, раздел `SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System`. Значение `1` разрешает только аутентификацию устройства и блокирует пользовательскую аутентификацию в службе `wlidsvc`, поэтому параметр должен быть равен `0` или отсутствовать. После изменения перезапустите приложение и проверьте вход; если окно не появилось — перезагрузите компьютер. Политика полезна в корпоративной среде, где администратор намеренно оставляет устройству только аутентификацию устройства, но на домашнем компьютере значение `1` означает, что вход в приложения Microsoft не заработает ни при каких настройках пакета, пока параметр не вернут в `0`, — и это стоит проверить прежде, чем переустанавливать что-то ещё.

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name EnterpriseDeviceAuthOnly
```

Если служба не запускается, проверьте системный журнал за последние сутки. Событие `7000` от Service Control Manager означает, что запуск службы не удался; текст события и код `WIN32_EXIT_B` помогут понять отказ. В событии 7000 причина написана словами, в `WIN32_EXIT_B` — числом. Отключённая служба может нарушить работу приложений и компонентов, которые зависят от аутентификации учетной записи Microsoft, причём неожиданным образом. Microsoft отдельно предупреждает: при отключении `wlidsvc` устройства с Windows 10 версии 1709 и новее перестают получать обновления функций, поэтому не отключайте её ради оптимизации.

```powershell
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Service Control Manager'; StartTime=(Get-Date).AddDays(-1)}
```

- Если команда перерегистрации завершилась без ошибок, а окно не появилось, перерегистрируйте `Microsoft.AccountsControl` и проверьте вход ещё раз в том же приложении.
- Если `Start-Service wlidsvc` возвращает ошибку, а `sc query` показывает `STOPPED`, изучите `WIN32_EXIT_B` и событие `7000` в журнале: они называют причину отказа, и повторять запуск без этого не стоит.
- Если `EnterpriseDeviceAuthOnly` равен `1`, снимите ограничение до значения `0` или удалите параметр, проверьте вход и при необходимости перезагрузите компьютер.
- Если после этих проверок окно не открылось, вернитесь к типу учетной записи и убедитесь, что перерегистрировали правильный пакет.

Начните с пакета. Дальше — компонент выбора учетной записи, служба и политика: каждая следующая проверка дороже предыдущей, а первые две закрывают причины, которые Microsoft описывает прямо, тогда как состояние службы чаще оказывается штатным, чем сломанным.

## Если нужна помощь со входом в приложения Microsoft

Могу помочь проверить вывод `Get-AppxPackage`, состояние `wlidsvc` и события системного журнала, чтобы определить, на каком звене останавливается вход. Вместе можно пройти перерегистрацию подходящего пакета и повторно проверить окно.

Напишите в чат на сайте, если вход по-прежнему не открывается или PowerShell показывает ошибку. Помогу разобрать её текст и выбрать следующий шаг; если совет помог, проверьте кнопку «Вход» повторно.
