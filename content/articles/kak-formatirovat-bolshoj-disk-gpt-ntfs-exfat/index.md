Диск на 4 ТБ сегодня уже никого не удивляет. На нём могут лежать фильмы, фотографии, резервные копии, виртуальные машины или рабочие проекты. Но с большим объёмом растёт цена ошибки: выбрали не ту схему разделов — получили недоступные 2 ТБ, отформатировали не в ту файловую систему — столкнулись с ограничениями другой ОС, неправильно подобрали параметры — получили лишние проблемы при работе с файлами.

При этом форматирование диска не требует особых знаний. Нужно лишь понимать несколько базовых вещей: **GPT или MBR, NTFS или exFAT, какой размер кластера выбрать и как потом проверить диск**.

Разберём всё по порядку.


## GPT или MBR: для дисков от 4 ТБ выбор почти предопределён

Начнём со схемы разделов.

**MBR** — старый стандарт разметки дисков. Он появился ещё в эпоху DOS и сегодня нужен в основном для совместимости со старым оборудованием и операционными системами.

Главное ограничение MBR — размер одного диска примерно **2 ТБ** при стандартном размере сектора 512 байт.

Поэтому диск на 4, 8 или 16 ТБ для обычного компьютера нужно размечать как **GPT**.

GPT — современная схема разметки. Она хранит таблицу разделов в нескольких местах и поддерживает диски намного большего объёма.

Есть и ещё один нюанс. GPT-диск обычно используют вместе с UEFI при загрузке Windows. Но для обычного внешнего диска UEFI вообще не имеет значения — GPT работает и как схема разметки накопителя для хранения данных.

### Что будет, если поставить MBR на диск 4 ТБ?

Полностью использовать такой диск в стандартной конфигурации не получится.

Windows покажет только доступный MBR-объём, а оставшееся пространство окажется за пределами адресуемой области.

Поэтому правило простое:

> **Диск больше 2 ТБ — GPT.**

Для нового накопителя на 4 ТБ и больше я бы вообще не рассматривал MBR, если нет конкретной причины использовать старую систему.


## Что такое файловая система

После выбора GPT нужно решить, **в какой файловой системе создать раздел**.

Файловая система определяет, как операционная система хранит и находит файлы на диске.

Самые известные варианты:

* **NTFS** — основной вариант для Windows;
* **exFAT** — хороший выбор для обмена файлами между Windows и macOS;
* **APFS** — основная файловая система современных macOS;
* **ext4** — распространённый вариант для Linux;
* **Btrfs** и **ZFS** — более специализированные файловые системы с дополнительными возможностями.

Это не просто разные названия одного и того же.

Например, Windows умеет полноценно работать с NTFS, а macOS штатно читает NTFS, но обычно не предоставляет полноценную запись без стороннего ПО.

Поэтому файловую систему нужно выбирать не по принципу «какая лучше», а по принципу **«где я буду использовать этот диск»**.


## Форматирование — не то же самое, что удаление файлов

Это важный момент.

Если выделить все файлы и нажать Delete, структура файловой системы останется прежней.

При форматировании создаётся новая файловая система.

Например, был диск NTFS с фильмами. Вы форматируете его в exFAT — старая файловая система исчезает, а вместе с ней теряется доступ к прежней структуре файлов.

При обычном быстром форматировании Windows не переписывает каждый сектор диска нулями. Поэтому быстрое форматирование не стоит воспринимать как способ надёжно уничтожить конфиденциальные данные.

И ещё одно: **форматирование уничтожает данные с точки зрения обычного доступа к ним**. Если информация важна, сначала сделайте резервную копию.


## Что такое кластер

Файл на диске занимает не произвольное количество байт, а определённое количество кластеров.

Например, если размер кластера 4 КБ, файл размером 5 КБ займёт два кластера — то есть 8 КБ дискового пространства.

Чем больше кластер, тем меньше служебных операций требуется при работе с большими файлами. Но маленькие файлы начинают занимать больше места.

Представим папку с миллионами небольших документов. Большой кластер там может привести к заметным потерям свободного пространства.

А теперь другой сценарий — архивы, ISO-образы, фильмы по 20–50 ГБ. Здесь большого количества мелких файлов нет, поэтому увеличенный кластер может иметь смысл.

Но не стоит ждать чудес.

Переход с 4 КБ на 64 КБ не превратит обычный HDD в SSD. Размер кластера влияет на структуру хранения и накладные расходы, а реальную скорость чаще ограничивают сам накопитель, интерфейс USB/SATA и характер нагрузки.


## Какую файловую систему выбрать обычному пользователю

Вот простая шпаргалка.

| Где используется диск                        | Что выбрать       |
| -------------------------------------------- | ----------------- |
| Только Windows                               | **NTFS**          |
| Windows + macOS                              | **exFAT**         |
| Только macOS                                 | **APFS**          |
| Только Linux                                 | **ext4**          |
| Linux-сервер с дополнительными возможностями | **Btrfs или ZFS** |
| Внешний диск для обмена файлами              | **exFAT**         |

Есть важное исключение.

Если диск используется для резервных копий Mac через Time Machine, файловая система и схема хранения зависят от сценария и версии macOS. Для современного Mac нельзя просто исходить из правила «любой внешний диск форматируем в exFAT».


## NTFS — мой выбор для диска под Windows

Если внешний HDD или SSD будет постоянно подключён к Windows-компьютеру, я бы выбрал **NTFS**.

У NTFS есть права доступа, журналирование, поддержка больших файлов и интеграция с Windows.

Для обычного диска с документами, играми, архивами и резервными копиями чаще всего достаточно стандартного размера кластера.

Не нужно ставить 64 КБ только потому, что диск имеет 8 ТБ.

Размер накопителя и размер кластера — разные вещи.


## exFAT — когда диск приходится таскать между компьютерами

Если один диск используется на Windows и macOS, ситуация меняется.

exFAT здесь часто оказывается самым практичным компромиссом.

Windows умеет с ним работать. macOS тоже умеет читать и записывать exFAT.

Нет необходимости устанавливать драйверы NTFS для записи на Mac.

Но есть цена за универсальность.

exFAT не даёт тех возможностей, которые есть у NTFS, APFS или некоторых Linux-файловых систем. Поэтому для диска, который постоянно работает внутри одного сервера, я бы не выбирал exFAT только ради его совместимости.

**Обменный диск — exFAT. Рабочий Windows-диск — NTFS.**


## APFS для Mac

Если накопитель предназначен только для компьютеров Apple, стоит смотреть в сторону APFS.

Это файловая система, рассчитанная на экосистему macOS.

Особенно логично использовать APFS с SSD и дисками, которые работают преимущественно с Mac.

Но если завтра этот же диск понадобится подключить к обычному Windows-компьютеру, начнутся проблемы с совместимостью.

Поэтому перед форматированием стоит ответить на один вопрос:

**«Мне нужна максимальная интеграция с одной ОС или совместимость с несколькими?»**


## ext4, Btrfs и ZFS для Linux

Для обычного Linux-компьютера ext4 остаётся понятным выбором.

Если речь идёт о сервере, ситуация интереснее.

**Btrfs** поддерживает снапшоты и другие функции, которые полезны для системного администрирования.

**ZFS** ориентирована на целостность данных, пулы хранения, снапшоты и другие серверные сценарии.

Но выбирать ZFS только потому, что «она надёжнее», без понимания её требований и архитектуры не стоит.

Для домашнего диска с фильмами ext4 обычно будет куда практичнее.


## Как форматировать диск в Windows

Для простого сценария достаточно Проводника.

Подключите диск.

Откройте **Этот компьютер**.

Найдите нужный накопитель.

Нажмите по нему правой кнопкой мыши → **Форматировать**.

Выберите файловую систему.

Для Windows — NTFS.

Для совместного использования Windows и macOS — exFAT.

Размер единицы распределения оставьте **по умолчанию**, если у вас нет конкретной причины менять его.

После этого нажмите **Начать**.

Но есть важный нюанс: если диск новый и имеет объём больше 2 ТБ, сначала проверьте его схему разделов.

Откройте **Управление дисками**.

Найдите накопитель.

Если он размечен как MBR, преобразуйте его в GPT — предварительно убедившись, что на диске нет нужных данных.


## Как создать GPT через Windows

Для продвинутого пользователя есть DiskPart.

Запустите терминал от имени администратора:

```text
diskpart
```

Затем:

```text
list disk
```

Вы увидите список физических дисков.

И здесь нужна максимальная внимательность.

Выбираем нужный диск:

```text
select disk N
```

где `N` — номер диска.

Проверяем ещё раз:

```text
detail disk
```

Если вы точно выбрали нужный накопитель, его можно очистить:

```text
clean
```

После этого:

```text
convert gpt
```

Создать раздел можно командой:

```text
create partition primary
```

А затем отформатировать его, например, в NTFS:

```text
format fs=ntfs quick
```

И назначить букву:

```text
assign
```

### Осторожно с `clean`

Команда `clean` удаляет информацию о разделах.

Если выбрать не тот диск, резервная копия в этой статье вас уже не спасёт.

Поэтому при работе с DiskPart правило одно: **проверяйте номер диска перед каждой операцией**.


## PowerShell

В Windows можно использовать и PowerShell.

Например:

```powershell
Get-Disk
```

покажет физические диски.

Для работы с дисками есть команды:

```powershell
Initialize-Disk
New-Partition
Format-Volume
```

Это особенно удобно при автоматизации и массовой настройке компьютеров.

Но для одного домашнего диска графический интерфейс обычно быстрее.


## Форматирование в macOS

В macOS используется **Дисковая утилита**.

Откройте её через Spotlight или:

**Программы → Утилиты → Дисковая утилита**

В меню **Вид** включите отображение всех устройств.

Выберите физический диск, а не случайный раздел.

Нажмите **Стереть**.

Для схемы выберите **GUID Partition Map**.

Это и есть GPT.

Дальше выберите файловую систему.

Для совместной работы Windows и Mac — exFAT.

Для использования в экосистеме Mac — подходящий вариант APFS.

Перед нажатием кнопки «Стереть» ещё раз проверьте выбранный накопитель.


## Linux

В графической среде GNOME можно использовать **Диски**.

Для работы из терминала применяют `parted`, `gdisk`, `mkfs` и другие инструменты.

Например, после создания раздела ext4 его форматирование может выглядеть так:

```bash
sudo mkfs.ext4 /dev/sdX1
```

Здесь `/dev/sdX1` — пример.

Нельзя копировать команду вслепую и менять одну букву «на глаз».

В Linux имя устройства определяет, какой диск вы сейчас форматируете.


## Нужно ли выбирать 64 КБ вместо 4 КБ?

Это один из самых популярных вопросов.

Если коротко — **обычному пользователю чаще всего не нужно ничего менять**.

Размер кластера 4 КБ подходит для огромного количества сценариев.

64 КБ может быть интересно для NTFS-раздела, на котором преимущественно лежат крупные файлы.

Например:

* видеоархив;
* ISO-образы;
* резервные копии;
* большие рабочие файлы.

Но если на диске лежат документы, фотографии, программы и множество небольших файлов, я бы оставил стандартное значение.

Больший кластер может увеличить объём потерянного пространства из-за внутренней фрагментации последнего кластера каждого файла.


## Что с inode в ext4?

В Linux есть ещё один параметр — inode.

Для каждого файла файловая система хранит метаданные в inode.

Если на диске будет огромное количество небольших файлов, количество inode становится важным.

Но здесь тоже не стоит менять настройки без причины.

Для обычного домашнего накопителя стандартные параметры ext4 подходят.

Настройка inode имеет смысл при проектировании специализированных файловых систем — например, для хранилища с миллионами мелких объектов.


## Как проверить новый диск

После форматирования я советую сделать ещё одну вещь — проверить сам накопитель.

Особенно если это новый HDD, восстановленный диск или накопитель, купленный на маркетплейсе у неизвестного продавца.

### SMART

SMART хранит диагностические данные накопителя.

На Windows для этого часто используют **CrystalDiskInfo**.

Посмотрите состояние диска, температуру и атрибуты ошибок.

Для SSD обращайте внимание и на показатели износа, если производитель их предоставляет.

### Проверка поверхности

Для HDD можно использовать специализированные программы проверки поверхности.

В Linux есть `badblocks`.

Но не запускайте разрушительные режимы проверки на диске с данными. Некоторые варианты тестирования записывают информацию поверх существующих данных.

### Проверка файловой системы

Сам диск может быть исправен, а файловая система — повреждена.

Windows предоставляет встроенные средства проверки, например `chkdsk`.

Linux использует семейство `fsck`.

Но эти инструменты проверяют структуру файловой системы. Они не заменяют SMART-тестирование самого накопителя.


## Большой диск с фильмами

Допустим, у вас HDD на 8 ТБ.

На нём лежат фильмы, сериалы и образы дисков.

Компьютер работает под Windows.

Я бы сделал:

**GPT + NTFS.**

Размер кластера — стандартный.

Если диск используется только для Windows и там действительно почти исключительно крупные файлы, можно рассмотреть 64 КБ.

Но разница не настолько велика, чтобы менять настройку без причины.


## Диск для фотографий и документов

Здесь я бы оставил:

**GPT + NTFS + стандартный размер кластера.**

Фотографии, документы и архивы имеют разный размер.

Поэтому универсальная настройка лучше специализированной.

И обязательно держите резервную копию.

Диск на 8 ТБ не становится надёжнее только потому, что он большой.

Наоборот — при его отказе можно потерять 8 ТБ данных за один раз.


## Диск для Windows и Mac

Здесь мой выбор:

**GPT + exFAT.**

Это один из самых простых вариантов.

Подключили к Windows — работает.

Подключили к Mac — работает.

Но есть важное правило: **не использовать один внешний диск как единственную копию важных данных**.

exFAT не спасёт фотографии от смерти самого накопителя.


## Linux-сервер

Для простого файлового хранилища я бы начал с ext4.

Если нужны снапшоты и дополнительные функции управления данными — смотрел бы на Btrfs.

Если строится серьёзное хранилище с ZFS-пулом, несколькими накопителями и понятной задачей — ZFS.

Файловая система не должна добавлять сложности просто ради галочки в списке возможностей.


## Как не потерять данные

Есть несколько правил, которые важнее выбора между NTFS и exFAT.

**Первое — резервная копия.**

Если данные существуют только на одном диске, это не резервная копия. Это единственный экземпляр.

**Второе — безопасное отключение.**

Не вытаскивайте внешний HDD во время записи.

Windows может использовать кэш записи, а приложение ещё может держать файл открытым.

**Третье — проверяйте SMART.**

Особенно если диск старый.

**Четвёртое — следите за температурой.**

Для HDD перегрев не становится полезнее от того, что на корпусе написано «8 ТБ».

**Пятое — проверяйте резервные копии.**

Бэкап, который никто никогда не пробовал восстановить, — это гипотеза о существовании бэкапа.


## Моя универсальная схема

Если не хочется разбираться в десятках параметров, используйте четыре правила.

**Windows → GPT + NTFS.**

**Windows + macOS → GPT + exFAT.**

**macOS → GPT + APFS.**

**Linux → GPT + ext4.**

Размер кластера — **по умолчанию**, если вы точно не знаете, зачем менять его.

Для дисков больше 2 ТБ — **GPT**.

А если на диске будут важные данные — заранее продумайте резервную копию.

### Шпаргалка

| Задача                     | Схема | Файловая система | Кластер                 |
| -------------------------- | ----- | ---------------- | ----------------------- |
| Windows                    | GPT   | NTFS             | По умолчанию            |
| Windows + macOS            | GPT   | exFAT            | По умолчанию            |
| Только Mac                 | GPT   | APFS             | По умолчанию            |
| Linux                      | GPT   | ext4             | По умолчанию            |
| Большие файлы на NTFS      | GPT   | NTFS             | Можно рассмотреть 64 КБ |
| Linux-сервер со снапшотами | GPT   | Btrfs            | Зависит от сценария     |
| Серверное хранилище ZFS    | GPT   | ZFS              | Зависит от конфигурации |

Главная мысль простая: **не существует одного «лучшего формата для большого диска»**.

Есть формат, который подходит конкретной задаче.

Если диск будет работать только с Windows — берите NTFS. Если его придётся носить между Windows и Mac — exFAT. Если это Linux-сервер — смотрите на ext4, Btrfs или ZFS.

А GPT для нового диска на 4 ТБ и больше — практически стандартный выбор.

И самое главное: **форматирование можно повторить, а потерянные фотографии — далеко не всегда.**
