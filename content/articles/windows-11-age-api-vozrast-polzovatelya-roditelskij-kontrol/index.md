Windows 11 получает новый механизм. Он позволит приложениям узнавать не дату рождения, а возрастную группу пользователя. Microsoft называет его **Windows Age API**.

8 сентября компания рассказала о системе в Windows Experience Blog. Тогда же появилась документация для разработчиков в Microsoft Learn. Сейчас Age APIs доступны участникам Windows Insider, позже — всем пользователям.

На первый взгляд кажется, что Microsoft добавила ещё одну функцию родительского контроля. Это не так. **Age API — не настройка Family Safety, а системный интерфейс для приложений.** И это изменение интереснее самого названия.

## Что такое Windows Age API

Раньше приложение само решало, как узнать возраст пользователя, чтобы ограничить контент. Теперь Windows отдаёт готовый возрастной сигнал. Схема простая: **учётная запись Microsoft → сигнал Windows → решение приложения.**

Microsoft объясняет идею так: возраст — возможность платформы. Разработчикам не нужно заставлять родителей и детей настраивать защиту отдельно в каждом приложении.

При этом приложение не получает дату рождения. Если в Microsoft Account указан возраст 14 лет, приложение не увидит `15.04.2012`. Оно увидит только группу. Дата рождения остаётся внутри системы. Такой подход связан с облачными функциями Windows — от синхронизации до [резервного копирования OneDrive](/articles/windows-11-onedrive-otkaz-ot-rezervnogo-kopirovaniya/).

## Windows не сообщает приложению точный возраст

Основной метод — `GetUserAgeRangeAsync`. Он возвращает одну из пяти групп:

| Возраст         | Сигнал Windows |
| --------------- | -------------- |
| Младше 10 лет   | 0–9            |
| 10–12 лет       | 10–12          |
| 13–15 лет       | 13–15          |
| 16–17 лет       | 16–17          |
| 18 лет и старше | 18+            |

Внутри API это два числа — `Lower` и `Upper`. Для 13–15 приложение получит `{13, 15}`, для 18+ верхняя граница — `INT32_MAX`. Если Windows не может дать сигнал, приложение получает `null`.

Важно: **`null` нельзя считать признаком «взрослый» или «ребёнок».** Разработчик должен предусмотреть запасной сценарий — например, собственную проверку возраста. Так API не откроет взрослый контент случайно, когда Windows не смогла получить данные.

## Второй сигнал — подтверждён ли возраст

Одного диапазона иногда мало. Магазин продаёт товар только пользователям 18+. Ему мало знать, что в аккаунте указано 25 лет. Нужна уверенность, что возраст подтверждён.

Для этого есть второй вызов — `GetAgeVerificationStatusAsync`:

* `Verified` — возраст подтверждён;
* `Unverified` — не подтверждён;
* `OptedOut` — пользователь отказался от проверки;
* `TemporarilyUnavailable` — статус временно недоступен;
* `NotApplicable` — проверка неприменима.

Разработчик учитывает все варианты. `NotApplicable` и `TemporarilyUnavailable` не означают ни «проверен», ни «не проверен». Получается схема из двух вопросов: в какой группе пользователь и подтверждён ли возраст. Дальше приложение решает, что делать.

## Зачем Microsoft понадобился отдельный Age API

Здесь самое интересное. Family Safety уже умеет ограничивать время работы Windows, блокировать приложения и игры, фильтровать сайты и показывать отчёты. Microsoft развивает эти функции и дальше. Но Family Safety решает другую задачу.

Родитель может сказать: «ребёнку нельзя играть больше часа в день» или «разрешены только сайты из списка». Age API отвечает иначе: **как приложению понять, какие ограничения применить к этому пользователю?**

Поэтому Microsoft не заменяет Family Safety, а добавляет уровень. Family Safety задаёт правила семьи. Age API даёт приложениям контекст возраста. Логика та же, что и с другими базовыми настройками системы — подробнее в [7 настройках Windows 11 после установки](/articles/7-nastroek-windows-11-posle-ustanovki/).

## Почему это лучше, чем спрашивать дату рождения

Приложению нужно ограничить чат для младше 13 лет. Ему не нужна дата рождения. Достаточно сигнала **группа 10–12** — чат отключён, задача решена.

Дата рождения остаётся в системе. Microsoft подчёркивает принцип: приложения получают только нужный сигнал, а не чувствительные данные. Компания по-прежнему хранит возраст в учётной записи, но **приложению не нужен доступ к исходной информации**. Для пользователя это разница.

## Что такое Microsoft Age Verification

Отдельно Microsoft развивает **Microsoft Age Verification (MAV)**. Идея простая: **проверил возраст один раз — используешь подтверждение в разных сервисах.** Статус хранится с Microsoft Account, приложения получают его через Age API.

Проверку уже используют магазины Microsoft в Сингапуре, Бразилии и Австралии. Список расширится с новыми региональными требованиями. Windows постепенно делает Microsoft Account источником идентификации и возрастового контекста.

## А что будет с локальной учётной записью Windows

Часто звучит вывод: «Перейду на локальную запись — Windows не узнает возраст, обойду контроль». Это не так.

Документация указывает: возрастовые сигналы доступны для **Microsoft Account**. Для других записей без административного значения `GetUserAgeRangeAsync` вернёт `null`, а `GetAgeVerificationStatusAsync` — `NotApplicable`.

Но это не сигнал «пользователь взрослый». Это отсутствие сигнала. Разработчик обязан использовать fallback — например, показать свою проверку возраста. Локальная запись не отключает ограничения. Выбор между локальной и облачной записью влияет на многое — от восстановления доступа до синхронизации. Подробнее — в материале [забыл пароль от ноутбука — как восстановить доступ к Windows](/articles/zabyl-parol-ot-noutbuka-kak-vosstanovit-dostup-k-windows/).

## А Family Safety при этом никуда не исчезает

Для родительского контроля Microsoft использует семейную группу и учётные записи Microsoft. Чтобы работал контроль экранного времени, устройство ребёнка должно быть в семейной группе. Для ребёнка рекомендуют стандартную запись, не администратора — так ниже риск обхода.

Через Family Safety родитель может ограничивать время устройства, ставить лимиты для приложений и игр, блокировать приложения, фильтровать сайты и поиск, смотреть активность ребёнка. Веб-фильтрация работает через Microsoft Edge, когда член семьи вошёл в Microsoft Account.

Age API это не заменяет. Он даёт приложениям сигнал от Windows, а они сами применяют нужные ограничения.

## Как это может выглядеть в обычном приложении

Microsoft приводит понятные сценарии — для каждого типа приложения свой набор ограничений:

- **Социальное приложение.** Пользователь в группе 10–12 лет — приложение отключает личные сообщения и ленту чужого контента. Для 18+ те же функции работают без ограничений.
- **Игра.** Группа определяет доступные функции и контент. Ребёнку не показывают материалы для взрослых, взрослому — показывают всё.
- **Магазин.** Перед покупкой товара с возрастным ограничением приложение проверяет группу и статус подтверждения. Без `Verified` покупка не пройдёт.
- **Медиасервис.** По группе выбирает рейтинг фильма. Детский профиль видит только разрешённый рейтинг, взрослый — любой.

Среди сценариев Microsoft прямо называет контент пользователей и соцсети, покупки и виртуальную валюту, медиа с возрастными рейтингами.

## Причём здесь Teams и Copilot

Проверка возраста затрагивает уже не только детские аккаунты. Microsoft готовит ограничения для части функций Teams Free там, где нужна верификация. Без проверки сервис может ограничить запись встреч и звонков, Copilot и часть сообществ. Статус обновляется до 24 часов.

Пример показательный. Age API нужен не только чтобы запретить игру. Он становится общим механизмом, который определяет, **какие возможности получит конкретный пользователь**. Похожий сдвиг к глубокой интеграции ИИ виден и в других местах Windows — например, в [Intelligent Terminal с ИИ](/articles/intelligent-terminal-windows-ai/).

## Что изменится для родительского контроля Windows 11

Раньше схема была такой: **родитель → Family Safety → ограничения Windows и сервисов.** Теперь добавляется слой: **Microsoft Account → сигнал Windows → приложение → свои ограничения.**

Это не замена Family Safety. Два механизма дополняют друг друга. Family Safety отвечает за правила семьи. Age API помогает приложениям учесть возраст без доступа к дате рождения. Microsoft называет это защитой, которая следует за пользователем между Windows и приложениями.

## Нужно ли что-то менять сейчас

Если родительский контроль уже настроен, переделывать его из-за Age API не нужно. Проверьте базу:

1. У ребёнка — Microsoft Account.
2. Запись в семейной группе.
3. Устройство подключено к Family Safety.
4. У ребёнка — стандартная запись Windows.
5. Включён Activity reporting, если нужны отчёты.

Этого достаточно для семейного контроля. Age API пока важнее разработчикам. Microsoft пишет, что API доступны участникам Windows Insider, остальным — позже. Отдельный `CheckAgeStatusAsync` выйдет с будущим обновлением.

## Мой вывод

Идея разделить возраст и дату рождения — удачная. Приложению редко нужен день рождения. Ему нужно понять: можно ли показывать контент и включать функцию.

Обратная сторона — учётная запись становится центром возрастовой политики Windows. Чем больше приложений доверят системному сигналу, тем сильнее зависимость от Microsoft Account.

Для семьи это меньше ручной настройки. Для разработчиков — единый способ узнать категорию. Для локальных записей — чаще fallback с собственной проверкой.

Windows 11 идёт не к одному переключателю «родительский контроль», а к другой модели: **Family Safety задаёт ограничения семьи, а Age API сообщает приложениям, для какой группы работает пользователь.** И это уже не просто функция контроля. Это новый слой Windows.
