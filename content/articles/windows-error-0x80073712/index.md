Ошибка `0x80073712` при установке обновления часто означает, что Windows не хватает нужных файлов или повреждено хранилище компонентов. Но код не всегда доказывает, что сломана именно ваша система: в марте 2026 года Microsoft подтвердила тот же сбой для конкретного preview-обновления и выпустила отдельное исправление.

Поэтому сначала запишите **номер KB**, который не устанавливается, и проверьте, нет ли для него известной проблемы. Если такого сообщения нет, переходите к штатной диагностике Windows. Запускать DISM, сбрасывать папки обновления и тем более переустанавливать систему наугад не нужно.

## Что означает ошибка 0x80073712

В таблице кодов Windows Update Microsoft связывает `0x80073712` с `ERROR_SXS_COMPONENT_STORE_CORRUPT`: хранилище компонентов находится в несогласованном состоянии. В нём Windows хранит файлы и сведения, необходимые для обслуживания системы и установки обновлений. В сообщении пользователю код обычно сопровождает текст: «Некоторые файлы обновления отсутствуют или имеют проблемы». Расшифровка кода приведена в [документации Microsoft Learn](https://learn.microsoft.com/en-us/troubleshoot/windows-server/installing-updates-features-roles/fix-windows-update-errors).

Это объяснение описывает **тип сбоя**, но ещё не отвечает, почему он произошёл именно у вас. Причиной может быть повреждение компонентов локальной Windows. Однако похожее сообщение может появиться и при проблеме с самим пакетом обновления.

### Когда ошибку вызывает конкретное обновление

Такой случай Microsoft зафиксировала весной 2026 года. После выпуска preview KB5079391 для Windows 11 24H2 и 25H2 часть устройств при установке получала `0x80073712`. Microsoft приостановила распространение пакета, а 31 марта выпустила внеплановое обновление KB5086672 с исправлением этой проблемы.

Это **не означает**, что любой такой код вызван неудачным KB. Это исторический пример для одного пакета; он не подтверждает сбой нынешних обновлений. Но случай показывает, почему опасно сразу считать хранилище компонентов повреждённым и запускать длинную цепочку команд. Для начала выясните, на каком именно обновлении остановилась установка.

## Шаг 1. Найдите номер обновления и проверьте его статус

Откройте **Параметры → Центр обновления Windows → Журнал обновлений** и найдите запись о неудачной установке. Запишите номер вида `KB1234567`, а также полный код ошибки. Если номер обновления не отображается, обратите внимание на название и дату попытки.

Затем найдите страницу этого KB на сайте поддержки Microsoft или откройте [панель состояния выпусков Windows](https://learn.microsoft.com/en-us/windows/release-health/). Ищите сообщения о приостановке распространения, известных проблемах и выпущенном исправлении.

- Если Microsoft подтверждает сбой **именно этого пакета**, следуйте указанному обходному решению или установите заменяющее обновление, когда оно появится. Не пытайтесь чинить хранилище Windows только потому, что код похож на повреждение компонентов.
- Если для KB нет известной проблемы, а ошибка повторяется на разных обновлениях, переходите к проверке самой системы. Это повышает вероятность локального сбоя, но не доказывает его без диагностики.

## Шаг 2. Запустите средство устранения неполадок

Для Windows 11 Microsoft предлагает начать со встроенной диагностики Центра обновления Windows в приложении **«Получить помощь»**. Она проверяет распространённые причины сбоев и может предложить автоматическое исправление. После завершения перезагрузите компьютер, снова откройте журнал обновлений и проверьте, повторяется ли ошибка. Шаги для Windows 10 и 11 Microsoft собрала в [руководстве по устранению проблем с обновлениями](https://support.microsoft.com/en-us/windows/deployment/updates-lifecycle/troubleshoot-problems-updating-windows).

Не переименовывайте вручную `SoftwareDistribution` и `catroot2` только на том основании, что увидели код `0x80073712`. Сброс кэша обновлений — не универсальное объяснение и не первый шаг для каждого случая.

## Шаг 3. Проверьте системные компоненты через DISM

Если проблема не исчезла и официальная страница проблемного KB не указывает на известный сбой пакета, Microsoft рекомендует для `0x80073712` восстановить системные файлы командой DISM.

1. Откройте меню «Пуск», найдите **Терминал** или **Командную строку** и запустите от имени администратора.
2. Выполните:

   ```cmd
   DISM.exe /Online /Cleanup-Image /RestoreHealth
   ```

3. Дождитесь завершения. Операция может занять несколько минут или дольше; не закрывайте окно, пока она работает.
4. Если DISM завершился успешно, выполните следующую команду:

   ```cmd
   sfc /scannow
   ```

5. Дождитесь завершения проверки, перезагрузите компьютер и повторите установку обновления. Такой порядок Microsoft приводит в [инструкции по восстановлению системных файлов](https://support.microsoft.com/en-us/windows/deployment/updates-lifecycle/troubleshoot-problems-updating-windows).

Команда проверяет текущий образ Windows и пытается восстановить обнаруженные повреждения. По умолчанию DISM может получать нужные файлы через Windows Update. Поэтому если сбоит именно источник восстановления или Центр обновления недоступен, команда способна завершиться другой ошибкой. Подробнее о DISM и источниках восстановления — в [документации Microsoft Learn](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/repair-a-windows-image?view=windows-11).

Например, `0x800f081f` означает, что не найдены исходные файлы для восстановления. **Это отдельная ошибка**, а не подтверждение того, что KB из первого шага неисправен. Для альтернативного источника DISM поддерживает параметр `/Source`, но источник должен подходить установленной системе. Не указывайте случайный ISO и не копируйте команды с индексом образа, не проверив версию и редакцию Windows.

SFC проверяет защищённые системные файлы. Это не заменяет проверку номера KB: сначала исключите подтверждённый сбой самого обновления, затем восстанавливайте Windows.

## Если DISM не помог

Если Windows загружается, но проблема с системными компонентами остаётся, в Windows 11 может быть доступен штатный вариант переустановки поверх текущей системы: **Параметры → Система → Восстановление → Исправление проблем с помощью Центра обновления Windows → Переустановить сейчас**. Подробное сравнение вариантов восстановления — в [инструкции по переустановке Windows без флешки](/articles/windows-11-pereustanovka-bez-fleshki-cloud-rebuild/).

Microsoft описывает этот способ как переустановку той же версии Windows с сохранением **файлов, приложений и настроек**. Во время процесса нужен интернет и подключение к питанию. На управляемых рабочей или учебной организацией устройствах эта функция может быть недоступна. Перед любым восстановлением всё равно сохраните важные данные.

Если пункта «Переустановить сейчас» нет, это не значит, что нужно сразу выполнять чистую установку. Проверьте, управляется ли устройство организацией, и используйте инструкции Microsoft для подходящего способа восстановления. Если DISM сообщил о недостающем источнике, сначала выясните, какой именно файл или компонент он не смог получить.

## Короткая развилка

- **Не устанавливается один конкретный KB:** сначала проверьте его страницу поддержки и release health.
- **Ошибка повторяется на разных обновлениях:** запустите встроенную диагностику; затем, если причина не выявлена, используйте DISM.
- **DISM сообщает `0x800f081f`:** проблема уже в поиске источника для восстановления; не подменяйте его случайным образом.
- **Восстановление компонентов не помогло:** рассмотрите штатную переустановку текущей версии Windows с сохранением данных, если она доступна.

## Частые вопросы

### Значит ли 0x80073712, что Windows повреждена?

Не обязательно. Код связан с состоянием хранилища компонентов, но Microsoft использовала его и для обозначения сбоя установки конкретного KB5079391. Поэтому сначала проверьте номер обновления и его статус.

### Нужно ли сразу запускать DISM и SFC?

Нет. Сначала проверьте статус KB. Если он не отмечен как проблемный и причина похожа на повреждение компонентов, Microsoft приводит последовательность DISM, затем SFC. Не запускайте команды, пока устанавливается другое обновление.

### Можно ли исправить ошибку переустановкой Windows через Центр обновления?

В Windows 11 может быть доступна функция «Переустановить сейчас». Она переустанавливает текущую версию и сохраняет приложения, файлы и настройки, но недоступна на части управляемых устройств. Перед запуском сохраните важные данные.

## Итог

`0x80073712` — повод проверить и обновление, и Windows, но не приговор системе. **Сначала выясните, какой KB не ставится и что о нём сообщает Microsoft.** Если известной проблемы пакета нет, переходите к диагностике и восстановлению компонентов. Такой порядок помогает не лечить компьютер командами, когда ошибка находится на стороне конкретного обновления.
