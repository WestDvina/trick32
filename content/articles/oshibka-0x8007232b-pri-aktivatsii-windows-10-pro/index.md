Ошибка 0x8007232B — это ошибка KMS-активации: Windows ищет KMS-хост и не находит его по DNS. Проверьте тип лицензии командой `slmgr.vbs /dlv`; если установлен ключ KMS-клиента (GVLK), замените его законным розничным или MAK-ключом либо активируйте по телефону.

GVLK из [документации Microsoft](https://learn.microsoft.com/en-us/windows-server/get-started/kms-client-activation-keys) не активирует розничную Windows, поэтому искать «правильный» ключ в интернете бессмысленно. Это не признак отказа серверов Microsoft.

```cmd
cscript c:\windows\system32\slmgr.vbs /dlv
```

## Почему Windows ищет KMS-хост

Код появляется, когда KMS-клиент не находит в DNS SRV-записи KMS-хоста. При автоматическом поиске система ищет записи `_vlmcs`; если нужная запись не обнаружена, Windows Script Host показывает сообщение `Error: 0x8007232B DNS name does not exist.`

Ключ KMS-клиента (GVLK) предназначен для корпоративной схемы лицензирования и автоматически направляет Windows к KMS-хосту, поэтому на домашнем компьютере без такого хоста любая попытка активации с этим ключом заканчивается одной и той же ошибкой снова и снова. В организации тот же код означает проблему с DNS или портом. Если активация слетела после изменения BIOS, это другой сценарий — [ошибка 0xC004F211 после обновления BIOS](/oshibka-0xc004f211-posle-obnovleniya-bios-kak-vernut-aktivatsiyu/).

## Как проверить установленный ключ

Проверьте статус активации:

```cmd
cscript c:\windows\system32\slmgr.vbs /xpr
```

В выводе `slmgr.vbs /dlv` поле `Description` со значением `VOLUME_KMSCLIENT` означает, что установлен ключ KMS-клиента. Поле `Partial Product Key` помогает проверить, что установленный ключ соответствует системе. Запишите это значение, чтобы сравнить его с тем ключом, который будете вводить.

`/dlv` показывает подробные сведения о лицензии, `/xpr` — срок активации. Для розничной лицензии и MAK активация бессрочная. Если в `Description` нет `VOLUME_KMSCLIENT`, не меняйте ключ по этой инструкции: код может относиться к другому сценарию.

## Как заменить ключ и завершить активацию

Для домашнего ПК подойдёт только законный ключ этой установки: розничный или MAK. Ключ KMS-клиента не заменяет лицензию и не активирует розничную редакцию. Команды выполняйте в командной строке с правами администратора:

```cmd
cscript c:\windows\system32\slmgr.vbs /ipk XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
cscript c:\windows\system32\slmgr.vbs /ato
```

`/ipk` устанавливает 25-значный ключ и заменяет прежний, `/ato` запускает онлайн-активацию для розничной лицензии или MAK. Ключ должен соответствовать выпуску Windows 10. Иначе не активируется. Если ключ приобретён для другого выпуска или другого типа лицензии, установка завершится ошибкой, поэтому повторять попытки с чужими или случайно найденными ключами бессмысленно, ведь система проверяет, что ключ действителен и применим к установленной операционной системе.

Сменить ключ можно и в интерфейсе: **Параметры → Обновление и безопасность → Активация**, пункт **Изменить ключ продукта**. После активации проверьте срок ещё раз командой из предыдущего раздела.

Если подходящего ключа нет, откройте **Параметры → Обновление и безопасность → Активация → Активировать по телефону**. Если такого пункта нет, нажмите Win+R и запустите:

```cmd
slui 4
```

Выберите расположение и нажмите «Далее» — появится Installation ID. Microsoft на странице офлайн-активации просит не звонить по указанному номеру, а открыть портал активации продукта, ввести Installation ID и получить Confirmation ID. Полученный код введите в окне активации Windows.

- Если ключ отклонён, проверьте, что он законный и соответствует выпуску Windows 10; если ошибка повторяется, сохраните вывод `slmgr.vbs /dlv` и передайте в поддержку Microsoft.
- На рабочем компьютере не меняйте ключ: KMS там может быть штатным. Проверку записи `_vlmcs._tcp` в DNS и доступность TCP 1688 выполняет администратор сети.
