После установки обновления Windows 10 Enterprise LTSC 21H2 показывает «Не удалось завершить обновления. Отмена изменений» и возвращается к прежнему состоянию. По этой надписи причину не найти: сначала нужен код ошибки, затем журналы, свободное место и хранилище компонентов.

## Надпись об отмене не показывает причину

Запишите код последней неудачной установки в журнале обновлений Центра обновления Windows. Рядом с ним указан номер KB пакета. Сведите трассировки в читаемый файл командой:

> **Get-WindowsUpdateLog**

Затем найдите код в **C:\Windows\Logs\CBS\CBS.log**; при сбоях Microsoft также советует проверить журнал событий **Setup**.

Код помогает выбрать направление проверки, но сам по себе не доказывает одну конкретную причину. Например, **0x800F0922** может означать проблему соединения с серверами обновлений или нехватку места в системном зарезервированном разделе; **0x80070070** указывает на недостаток свободного места. Коды **0x80073712** и **0x800f0831** связаны с повреждением хранилища компонентов, а **0x800f081f** — с отсутствующим исходным пакетом или файлом.

## Проверьте место, прежде чем чинить хранилище

Посмотрите остаток места на системном томе и в разделе восстановления. Для раздела Windows RE Microsoft указывает минимум 300 МБ общего размера, а для систем новее Windows 10 версии 2004 — не менее 200 МБ свободного места. Это требования к среде восстановления, а не отдельный норматив для ежемесячного кумулятивного обновления.

Состояние Windows RE показывает команда:

> **reagentc /info**

Если код указывает на хранилище компонентов, проверьте его и только затем запускайте восстановление: в командной строке от имени администратора выполните команды по порядку.

> **DISM /Online /Cleanup-Image /ScanHealth**
>
> **DISM /Online /Cleanup-Image /CheckHealth**
>
> **DISM /Online /Cleanup-Image /RestoreHealth**
>
> **sfc /scannow**

Первая команда показывает, исправен ли образ, ремонтопригоден ли он или не поддаётся восстановлению. Восстановление выполняют только для ремонтопригодного образа; последняя команда проверяет системные файлы. Журнал CBS содержит сведения о ходе установки и отката.

## Повторите установку именно того же пакета

После проверок найдите по номеру KB тот же кумулятивный пакет в Каталоге Центра обновления Майкрософт (англ. Microsoft Update Catalog). Для LTSC 21H2 выбирайте пакет для сборки **19044** и нужной разрядности. С февраля 2021 года кумулятивное обновление включает последний стек обслуживания, поэтому отдельный SSU не требуется.

Установить скачанный файл **.msu** можно через DISM, подставив его фактический путь:

> **Dism /Online /Add-Package /PackagePath:"путь к файлу .msu"**

После перезагрузки проверьте журнал обновлений и номер сборки. Если обновления управляются через WSUS или Configuration Manager, ручная установка идёт в обход этого канала и не меняет корпоративную политику.

В [разборе для LTSC 21H2](https://trick32.ru/articles/ne-udalos-zavershit-obnovleniya-otmena-izmeneniy-chto-proverit-na-ltsc-21h2/) собраны значения кодов и последовательность проверки журналов, разделов и хранилища компонентов. Сама LTSC 2021 получает обычные обновления безопасности до 12 января 2027 года; дата 2032 года относится только к IoT Enterprise.

## Если сбой повторится

- Если обнаружен **0x800F0922** и компьютер подключён к рабочей сети через VPN → отключитесь от сети и выключите VPN, затем повторите установку. Также проверьте свободное место в системном зарезервированном разделе: Microsoft указывает обе возможные причины.
- Если получен код **0x800f081f** → найдите по номеру KB тот же пакет для сборки **19044** в Каталоге Центра обновления Майкрософт и попробуйте установить его вручную.
