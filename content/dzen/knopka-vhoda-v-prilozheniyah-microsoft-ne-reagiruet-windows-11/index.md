В Центре отзывов, Xbox или Solitaire нажимаете «Вход», а окно не появляется — и ошибки тоже нет. В описанном случае сброс и переустановка приложений не помогли; разберёмся, какой системный компонент проверить вместо очередного сброса.

Этот симптом сообщён для Windows 11 26H1, сборки 28000.3501. Это единичное описание, а не подтверждённая Microsoft массовая проблема или известная ошибка этой версии.

Кнопка приложения передаёт запрос системному брокеру входа. Поэтому переустановка самого приложения и восстановление окна авторизации — не одно и то же: для начала важно определить, личная у вас учетная запись или рабочая.

## Сброс приложения не чинит отдельный пакет входа

Web Account Manager (WAM) — системный брокер аутентификации Windows. Приложение обращается к нему, а не рисует окно входа самостоятельно; пакет приложения и пакет, связанный с учетной записью, — разные компоненты. Сброс Xbox или Центра отзывов не перерегистрирует пакет входа из папки SystemApps.

В документации Microsoft описан похожий отказ аутентификации в Outlook и некоторых других приложениях, а также приведено восстановление пакетов. Для Центра отзывов, Xbox и Solitaire отдельной инструкции нет, поэтому этот способ стоит считать проверкой по аналогии, а не гарантированным исправлением.

## Личная и рабочая учетные записи используют разные пакеты

Откройте **Параметры → Учётные записи → Ваши сведения** и определите тип учетной записи. Для личной, например с адресом `@outlook.com` или `@hotmail.com`, нужен `Microsoft.Windows.CloudExperienceHost` (Live ID). Для рабочей или учебной — `Microsoft.AAD.BrokerPlugin`.

Проверьте только подходящий пакет в PowerShell. Команда показывает сведения об установленном пакете в текущем профиле; пустой вывод означает, что он не найден. Не запускайте обе команды наугад: успешная регистрация другого пакета не исправит вход вашей учетной записи.

Для личной учетной записи:

> **Get-AppxPackage Microsoft.Windows.CloudExperienceHost**

Для рабочей или учебной:

> **Get-AppxPackage Microsoft.AAD.BrokerPlugin**

Если нужного пакета нет, запустите PowerShell **от имени администратора**. Для перерегистрации используйте команду `Add-AppxPackage -Register` с манифестом именно этого пакета из системной папки `SystemApps`; такой шаг нужен только при отсутствии пакета. Перерегистрация читает файл Windows на компьютере и не скачивает его из интернета.

После завершения закройте приложение полностью, запустите его заново и проверьте кнопку «Вход». Если проверка показывает, что пакет уже есть, не запускайте восстановление вслепую: описанный шаг рассчитан на отсутствующий пакет и сам по себе не подтверждает повреждение уже установленного.

## Если окно так и не появилось

Если подходящий пакет на месте, а окно выбора учетной записи не открывается, проверьте компонент `Microsoft.AccountsControl`. Microsoft связывает такой симптом с компонентом выбора учетной записи и предлагает перерегистрировать его из PowerShell с правами администратора; если пакет отсутствует, для этого используют его манифест из `SystemApps`.

Если после этого окно не появилось, проверьте службу `wlidsvc` — Microsoft Account Sign-in Assistant. Значение `Start` равно `3`, когда служба запускается вручную; `4` означает, что она отключена. Остановка сама по себе не всегда говорит о неисправности: служба может запускаться по требованию.

> **sc query wlidsvc**

Если параметр `Start` равен `4`, а служба не должна быть отключена, можно вернуть ручной запуск и запустить её в PowerShell от имени администратора. В команде настройки службы после `start=` нужен пробел.

> **sc config wlidsvc start= demand**

> **Start-Service wlidsvc**

Если `Start-Service` завершился ошибкой, а состояние службы — `STOPPED`, не повторяйте запуск вслепую: сверьте код `WIN32_EXIT_B` и событие `7000` от Service Control Manager в системном журнале. Ещё проверьте параметр `EnterpriseDeviceAuthOnly` в разделе реестра `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System`: значение `1` блокирует пользовательскую аутентификацию для `wlidsvc`. На рабочем устройстве сначала уточните у администратора, не задано ли это ограничение намеренно.

- Если перерегистрация подходящего пакета прошла без ошибки, но окно не появилось — проверьте `Microsoft.AccountsControl` и перерегистрируйте компонент из PowerShell с правами администратора.
- Если `Start-Service wlidsvc` завершился ошибкой, а `sc query wlidsvc` показывает `STOPPED` — сначала изучите `WIN32_EXIT_B` и событие `7000` в системном журнале.
- Если `EnterpriseDeviceAuthOnly` равен `1` — выясните, задано ли ограничение администратором; если оно не требуется, параметр должен быть равен `0` или отсутствовать.

Эти проверки не гарантируют результат для Центра отзывов, Xbox и Solitaire: Microsoft описывает перерегистрацию пакетов для других приложений и отдельно — сбой окна выбора учетной записи. Границы метода, журнал службы и связанные параметры разобраны [в основной статье о молчащей кнопке «Вход» в Windows 11](https://trick32.ru/articles/knopka-vhoda-v-prilozheniyah-microsoft-ne-reagiruet-windows-11/).
