Звуковая карта Lexicon Lambda перестала запускаться после перехода на Windows 11 26H2. В Диспетчере устройств — жёлтый треугольник и код 10, в наушниках тишина, ASIO-драйвер карту не видит. Переподключение в другой порт не помогает. Переустановка драйвера тоже.

Самое неприятное начинается, когда открываешь страницу Microsoft с известными проблемами. Там эта ошибка есть. Но рядом стоит слово Mitigated. И вот его легко прочитать как «починили». Это не так.

## Что значит Mitigated

В release health Windows 11 26H2 есть пункт про USB-аудио. Microsoft перечисляет симптомы: устройство показывает Code 10, звука нет, регуляторы громкости не отвечают или стоят на нуле, настройки звука недоступны. И отдельная оговорка: проблема касается только устройств USB Audio Class 1.0.

Запись открыта 11 сентября 2026 года. Последний раз её обновляли 29 сентября. Статус — Mitigated. На 3 ноября он всё ещё Mitigated.

Слово означает, что Microsoft снизила остроту проблемы, но не закрыла её. Часть симптомов убрали. Code 10 остался. Компания пишет, что работает над исправлением в будущем обновлении, и не называет сроков. Для немедленного обходного решения отправляет IT-администраторов в Support for Business. Пользовательского рецепта на странице нет.

Вот это и есть главная ловушка. Формально Microsoft проблему признала. Фактически для владельца карты Class 1.0, которая не запускается в обычном стереорежиме, ничего не изменилось.

## Что на самом деле произошло

8 сентября 2026 года выходит KB5124008 для Windows 11 24H2 и 25H2. В известных проблемах появляется пункт про USB-аудио: Code 10, отсутствие звука, неработающая громкость.

14 сентября выходит внеплановое KB5129195. Оно исправляет часть истории. Дословная формулировка Microsoft: некоторые устройства USB Audio Class 1.0 нормально работали в стандартном стерео, но падали при использовании многоканального звука, включая 8-канальный и 3D-режимы. Именно это обновление и закрыло.

Дальше важная деталь, которую часто пропускают. В статье KB5129195 прямо сказано: другие аудиосимптомы этим внеплановым обновлением не устранены. В списке известных проблем самого обновления остаётся пункт про USB Audio Class 1.0 с ошибкой Code 10 или без вывода звука. То есть ошибка запуска никуда не делась.

Проще говоря, KB5129195 вернул звук части устройств. Тем, которые уже работали в стерео, но ломались при переключении на многоканальный режим. Устройство, которое не стартует вообще, это обновление не лечит.

Потом выходят KB5134133 от 26 октября и предпросмотр KB5127936 от 28 октября. В обоих снова есть известная проблема с USB-аудио и Code 10. 28 октября 26H2 становится доступной всем подходящим устройствам — вместе с нерешённой ошибкой.

## Почему драйвер Lexicon не спасает

Стандартный совет Microsoft для Code 10 звучит логично: обновите драйвер. Для обычного сбоя это правильный путь. Здесь он упирается в устройство системного стека.

USB-карту класса 1.0 обслуживает системный драйвер usbaudio.sys. Microsoft прямо пишет: когда аудиоустройство при перечислении Plug and Play сообщает о совместимости с USB Audio, система сама загружает USBAudio. Проприетарный драйвер-адаптер такому устройству не нужен.

ASIO-драйвер Lexicon v2.7 работает выше. Он не заменяет системный драйвер и не может запустить карту, которую не запускает Windows. Пока usbaudio.sys возвращает ошибку, открывать ASIO нечего.

Отсюда и наблюдение из Microsoft Q&A: пользователь переустанавливал драйвер, перерегистрировал DLL, перезапускал Audiosrv и AudioEndpointBuilder, менял порты USB 2.0 и 3.0. Результата ноль. Это не значит, что драйвер плохой. Это значит, что ошибка приходит не из него.

Код 10 у аудиоустройства вообще бывает разным. Иногда виноват универсальный драйвер, который подхватил не то устройство, и тогда помогает возврат правильного пакета. Но тут другой уровень: не драйвер карты, а известная ошибка Windows.

## Как проверить, что у вас тот же случай

Сначала посмотрите код. Откройте Диспетчер устройств, найдите звуковую карту, откройте свойства. Нужна строка «This device cannot start (Code 10)» или русский вариант «Запуск этого устройства невозможен (код 10)».

Потом проверьте, что в ошибке именно медиаустройство. В PowerShell от администратора выполните команду Get-PnpDevice с ключами -Class MEDIA, -PresentOnly и -Status ERROR,DEGRADED,UNKNOWN. Она покажет присутствующие устройства класса MEDIA, которые находятся в ошибке, деградации или неизвестном состоянии. Если в списке только ваша карта — картина сходится.

Уточнить код можно через свойство Problem в выводе Get-PnpDevice по классу MEDIA. У проблемного устройства там будет 10. Свойство приходит из WMI-класса Win32_PnPEntity и в документации самого командлета не описано, поэтому при пустом поле смотрите вкладку «Общие» в свойствах устройства.

Дальше проверьте драйвер. Если устройство опознаётся как USB Audio-совместимое, поставщик драйвера — Microsoft, а не Lexicon. Так и должно быть. И последнее: убедитесь, что система действительно 26H2. Утилита winver покажет версию и сборку без похода в параметры.

## Что делать, пока исправления нет

Первое — поставить последнее доступное накопительное обновление. На 28 октября это предпросмотр KB5127936 или более новое. Через Центр обновления Windows: Settings → Windows Update → Check for updates. Если обновление не приходит, нужный KB ищут по номеру в каталоге Microsoft Update Catalog и ставят вручную. После установки — перезагрузка и повторная проверка карты.

Чуда ждать не стоит. KB5127936 сам ещё содержит Code 10 в известных проблемах. Обновление нужно, чтобы не пропустить момент, когда исправление выйдет.

Второе — если карта работает в стерео, но падает в многоканальном режиме, попробуйте 2-канальный режим. Microsoft в статьях KB5124008 и KB5129195 для 25H2 и 24H2 пишет, что части пользователей это возвращало звук. KB5129195 закрывает 8-канальный и 3D-режим, но применяется к 25H2 и 24H2. Прямого указания для 26H2 в документации нет: там своя ветка сборок.

Третье — если Code 10 в обычном стерео, пользовательского обходного пути нет. Microsoft предлагает ждать будущего обновления. Если звук нужен сразу, подключите другое аудиоустройство: по документации Microsoft проблема ограничена USB Audio Class 1.0, поэтому карта другого класса или устройство с собственным драйвером производителя — временный выход. Организациям с немедленной потребностью Microsoft предлагает Support for Business.

Четвёртое — проверьте карту на другой машине, где она работала раньше. Если и там Code 10, это не доказывает поломку карты: проблема документирована не только для 26H2, но и для 24H2, 25H2 и других версий. Зато тест отделяет вашу карту от системной ошибки, если на другой машине она запускается.

## Чего делать не стоит

Не пытайтесь удалить KB5124008 на 26H2. Статья KB5124008 относится к 24H2 и 25H2; в 26H2 его изменения входят кумулятивно, но исправления Code 10 там нет — он остаётся в известных проблемах и в KB5127936 от 28 октября. Пользователь из Q&A сообщает, что wusa удалить обновление не дала. Это его наблюдение, а не инструкция Microsoft.

Не лезьте в реестр за «правильными» параметрами USB-аудио. Microsoft не публиковала для этой проблемы ни ключей, ни значений. Всё, что найдётся в чужих советах, — догадки.

Не отключайте проверку подписи драйверов и не подсовывайте старые пакеты USBAudio из сторонних сборок. Это лечит другую болезнь и добавляет новую.

Не считайте STATUS_DEVICE_DATA_ERROR отдельным кодом Microsoft для этой истории. В release health такого кода нет: он пришёл из описания пользователя в Q&A. Для Microsoft симптом называется Code 10.

И не покупайте новую карту, пока не проверили её на другой системе. Известная проблема класса не делает вашу конкретную карту мёртвой.

## Что в итоге

Microsoft признала ошибку USB Audio Class 1.0, но полностью не исправила. KB5129195 закрыл только многоканальную часть. Code 10 в стереорежиме остаётся в известных проблемах даже в предпросмотре от 28 октября. Сроков нет, пользовательского обходного пути тоже.

Это тот случай, когда честный ответ звучит неприятно: ждать обновления и проверять release health. Всё остальное — переустановка драйверов, правка реестра, удаление KB — на 26H2 выглядит активностью, но проблему не решает.
