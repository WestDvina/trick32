# Правила проекта trick32.ru

## Git: коммит и push только по явной команде

- НИКОГДА не выполнять `git commit`, `git push`, `git add` (с последующим коммитом), `git tag`, `git merge`, `git rebase --continue` и любые другие действия, создающие коммиты или отправляющие их на удалённый репозиторий, без прямой явной команды пользователя.
- Разрешено без отдельного разрешения делать только безопасные, не изменяющие удалённый репозиторий операции: `git status`, `git log`, `git diff`, `git fetch`, `git pull --rebase` (только если пользователь просил подтянуть изменения), `git ls-remote`.
- Если пользователь просит «закоммить», «запушь», «залей на GitHub» — это явная команда, можно выполнять.
- Во всех остальных случаях: подготовить изменения, показать `git status`/`git diff` и предложить команду, но НЕ выполнять её.

## Теги и категории: не плодить

- **Теги берём только из уже существующих** в `content/articles/**`. Перед простановкой сверяться с текущим списком тегов.
- **Новый тег придумывать только если** под статью действительно нет ни одного подходящего существующего тега.
- **Не добавлять** синонимы, падежные варианты и дубли уже существующих тегов (например, не `обновления`, если есть `обновление`).
- **Единый вид:** русские слова — по-русски (кириллицей), английские/технические термины — латиницей, как принято (`windows-11`, `tpm`, `ssd`). Названия проектов — как в оригинале (`shifer`).
- **Категории не расширять** без явной необходимости. Текущий набор: `windows`, `os`, `ms-office`, `hardware`, `digital-life`, `bots`.

## Статьи: всегда отдельная папка

- Каждая статья — это page bundle: `content/articles/<slug>/index.md` (slug — латиница через дефис).
- Картинки статьи кладём рядом с `index.md` в ту же папку (не плоским файлом `slug.md`).
- OG-картинка генерируется автоматически в `static/og/<slug>.jpg`; в frontmatter её не пишем.

## Оформление статей

- Команды, скрипты и то, что пользователь копирует для запуска, оформляем **блоками кода** (фенс с языком: ```` ```powershell ```` или ```` ``` ````), а НЕ одинарными обратными кавычками на отдельной строке.
- Одинарные кавычки (inline-код) — только для коротких упоминаний внутри предложения: имя параметра, путь, имя задачи, значение реестра.
- Так же, как в остальных статьях сайта: для консистентного вида и удобного копирования.

## Перелинковка: только в тексте, без блока «Читайте также»

- **Не добавлять** блок «Читайте также» и любые списки ссылок в конце статьи. Никогда.
- Внутренние ссылки ставим **только прямо в текст**: в предложение, где ссылка логично продолжает мысль.
- Ссылка должна читаться как часть фразы, а не как вставка «см. также». Текст вокруг неё переписываем под ссылку, а не наоборот.
- Не ломать при этом абзац: одна ссылка на мысль, без грозди из трёх подряд.
- Если ссылку некуда вставить естественно — лучше не ставить вовсе.
- Ориентир: 2–5 внутренних ссылок на статью, разнесённых по разным разделам.

## Конец статьи: всегда предлагать помощь

- Каждая статья заканчивается коротким блоком помощи — **по теме статьи**, а не общим «обращайтесь».
- Объясняем, в чём именно помогаем: называем конкретные задачи из этой области, а не «решу любые проблемы с компьютером».
- Формат: один короткий раздел или 2–3 абзаца в конце, после FAQ. Без прайс-листа, без рекламных восклицаний.
- Контакты: чат на сайте (кнопка справа внизу) и запасной — **@walgo**. Цену называем до начала работы: от 500 ₽.
- Если по теме уместна страница услуги — ссылаемся на неё в тексте, а не блоком в конце.
- Тон: спокойная констатация. «Помогаю с …» — а не «Я лучший специалист по …».

## Ссылки: без оборотов-подводок

- Запрещены служебные приписки к ссылке: «разбирал в этой статье», «разбирал здесь», «разбирал в этой теме», «здесь разложил», «подробнее читайте», «об этом — в отдельном материале», «в разборе», «см. также».
- Ссылка встраивается в предложение как его часть: анкор продолжает мысль, вокруг — обычный текст, а не подпись под ссылкой.
- Если тянет написать такой оборот — переписываем фразу целиком, чтобы он стал ненужным.
- Плохо: «…слабее чистой установки: разбирал все режимы сброса отдельно.»
- Хорошо: «…слабее чистой установки, а какие режимы сброса бывают и что они стирают, стоит посмотреть до нажатия кнопки.»

## OG-картинка: только на GitHub

- OG-карточка формируется **на GitHub** во время сборки (GitHub Actions) из `tools/og-image/`.
- Локально картинку не рисуем и не запускаем генератор «на всякий случай».
- В frontmatter `images:` не прописываем — сборка подставляет `/og/<slug>.jpg` сама.
- Руками `.jpg` в `static/og/` не кладём и не коммитим: единственный источник карточки — сборка на GitHub.
- Хук карточки (3–5 слов) — по желанию, в `tools/og-image/hooks.json`. Если хука нет, сборка соберёт его из заголовка.
